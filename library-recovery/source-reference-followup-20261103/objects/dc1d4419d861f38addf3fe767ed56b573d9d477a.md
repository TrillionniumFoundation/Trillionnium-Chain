# Immutable model release roots and bounded acquisition

This is an M09 implementation contract for I05/I09 in the
[sole development plan](../../TRNM_AI_NATIVE_BLOCKCHAIN_DEVELOPMENT_PLAN.md).
The source baseline is Chain #683, commit
`1c7e8ab7cd6a321cad4e6c7f7e8a197d7b3be14c`. Existing TCM1, TCR1, TCD1,
CPR2 and their signed domains remain unchanged. No production flag is promoted.

## Release identity: TMR1

`CellModelReleaseRootV1` commits the entire canonical TCD1 object, an explicit
router-roster commitment and up to 16 canonical direct parent release roots.
The original closure already binds family, base, parent model, tokenizer,
layout, runtime, selected generation, loader profile, paths, roles, payload
hashes/sizes and the complete declared dependency graph. TMR1 adds an explicit
router identity even for an empty router set; omitting a router changes the root.

| Field | Canonical encoding |
| --- | --- |
| Version | `TMR1` |
| Original closure | u32 big-endian byte length, then exact TCD1 bytes |
| Router roster | 32-byte SHA-256 commitment |
| Direct lineage | u8 count, then ascending, unique, nonzero 32-byte parent root IDs |

The root ID is SHA-256 of `trnm.cell-model-release-root.v1\0` followed by the
entire encoding. The router commitment hashes
`trnm.cell-model-router-roster.v1\0`, a u16 count, then each Router-role file in
canonical path order: u16 path length, path bytes, manifest ID, payload SHA-256
and u64 payload size. The maximum root length is the original 1 MiB TCD1 cap
plus the fixed wrapper and 16 parents. Bounds precede decoding/allocation;
truncation, trailing bytes and a mismatched router commitment are rejected.

`verify_parent_roots` checks actual parent root bytes, exact coverage, family
and strictly older generation. Empty lineage explicitly declares an origin.
This method does not independently discover omitted ancestry or authenticate
the publisher. `prepare-model-root` checks every supplied parent; a fetch checks
the independently pinned root and original loader context. Fetching alone
therefore binds an owner's lineage declaration, not a verified transitive history.

`fetch_model_release_to_file` composes the original release downloader. It
preflights every original member manifest before any payload, shares one
connection/response-byte/time reservation across the closure, checks every
chunk and complete payload, and only then publishes exact TMR1 with the original
create-only marker owner. An existing output is never replaced. TCD1 can still
be fetched from the same CAS byte-for-byte for the existing Hepta loader.

The model root and closure pins must be supplied independently of peers. CPR2
continues to authenticate its original embedded TCR1, not TMR1 metadata. TMR1
has no new signature authority and cannot grant CURRENT or FinalUse. The current
Hepta #4497 profile remains an exact 11-file SmolLM2 loader; general router and
layout support requires an explicit new consumer profile and separate evidence.

## Verified chunk delta: TCX1

`CellChunkDeltaV1` is a byte-reuse recipe in the existing CAS. It is not an
executable patch, tensor instruction stream or approximate arithmetic update.
The exact base manifest and complete target manifest are committed, followed by
one u32 source index per target chunk. `u32::MAX` denotes a new CAS chunk. Any
reused chunk must have the same length and SHA-256; the first matching base index
is mandatory so duplicate base chunks cannot produce alternate canonical recipes.

The encoding is `TCX1`, 32-byte base manifest ID, u32 target-wire length, target
TCM1 bytes, u32 source count and source indices. The ID domain is
`trnm.cell-chunk-delta.v1\0`. Length/count/index bounds are checked before use.
Recipe verification requires the actual pinned base manifest, not a claimed
payload hash or file path.

`fetch_delta_to_file` requires independent delta, base and target pins. It
reserves aggregate base-plus-target logical bytes and chunk checks, enforces the
per-object maximum on both objects, and verifies the complete actual local base
before target metadata admission. The target then enters the same downloader:
existing chunks are reused by content address, only absent chunks are fetched,
and the full ordered target SHA-256 is verified before create-only publication.
The original absolute deadline covers base verification and target acquisition.
No probe/retry receives a new connection or response-byte allowance.

Cross-version cache deduplication remains keyed by chunk SHA-256. The delta
reuses those bytes; it does not introduce a second store. Original contextual
TCM1 manifests can differ between versions even when base chunk bytes coincide.

## Discovery and transport

The existing finite multi-bootstrap rendezvous remains the directory. It does
not follow referrals, so recursive hop count is zero. TTL, bootstrap/connection,
record/signature and total response budgets retain their original limits.
Ed25519 and ML-DSA discovery now retain the actual bootstrap provenance of each
current verified statement and select at most eight endpoints using balanced
bootstrap contribution, IPv4 /24 or IPv6 /64 prefix diversity and actual IP
diversity. Selection follows all high-water, equivocation and withdrawal checks.
Newer statements cannot inherit provenance from older addresses or TTLs.

These are conservative selection heuristics among received eligible candidates.
They cannot recover providers hidden by every directory or prove independent
administrators. A full history quota still refuses new identities; it is never
reset to make discovery appear successful. Multiple keys, addresses or prefixes
are not proof of Sybil resistance or independent custody.

Original downloads now quarantine peers that supply complete invalid frames,
wrong manifests or corrupt chunks for that single session. The quarantine is
shared across all release members. Missing objects, IO interruption and legacy
inventory refusal are not corruption verdicts. Already in-flight reads may
finish, and all their response bytes remain charged. No permanent ban or payment
penalty follows from this local decision.

Explicit `rarest-first-v1` scheduling uses the new `TCI1`/`TIS1` inventory wire
and the original workers, backpressure and persistence owner. Each query covers
at most 256 chunk slots; its response has at most 32 bitmap bytes and zero
unused trailing bits. Inventory is only an untrusted presence/length hint.
Observed scarcer chunks are scheduled first and claimed suppliers are preferred,
while stale or zero hints retain ordinary byte-fetch fallback. Actual bytes
always pass the original hashes. Inventory probes consume the original total
deadline, connections and response bytes. Default callers do not probe inventory.

## Retention, history and admission

The [release retention catalog](CELL_RETENTION_V1.md) uses a fresh TCA1 namespace
over the original retention arena. It binds complete TMR1 roots to exact original
physical obligations, responsible owner, declared failure domain/replica slot,
funding identity, lease and repair deadline. Pending reservations protect every
declared dependency; expiry alone cannot remove a root. The retirement path
checks all remaining references before releasing an object. Shared obligations
remain protected until every referencing release has completed explicit retirement.

The local catalog is not the native monetary ledger. Connecting a complete
release-level operation to actual M12/Node escrow, qualifying independent
replicas, renewal funding and 72-hour WAN repair/service evidence remain required.
The current profile uses complete replicas, not an unimplemented erasure code.
Checksums and local locks are not independent protection against full-host rollback.

Local inference still requires the original controlled parser, resource admission,
CURRENT selection and FinalUse checks after content verification. A completion
marker or retention acknowledgment cannot bypass those owners. Revocation and
chain reorganization cannot erase pending physical effects or promised history.

Use repository-pinned Rust 1.95.0 and the unchanged lockfile:

```sh
bash scripts/project-preflight.sh
# The all-feature suite needs the original, pinned ML-DSA provider. The helper

model_pq_temp="$(mktemp -d)"

RUNNER_TEMP="$model_pq_temp" GITHUB_ENV="$model_pq_env" bash scripts/ci/prepare_pq_provider.sh
set -a

```

all-feature Clippy completed with `-D warnings`; the existing SQLite boundary
build script still reported its unqualified loader-directory environment. That

`fbe64b5b4662405980becd75c81c9ef699a78b56449d71ed33185531db851c69`.
These are local observations, not remote CI results or infrastructure acceptance.

The tests include independent Python/Rust identity bytes; every truncated root

Synthetic bytes and local processes establish these software properties only.
