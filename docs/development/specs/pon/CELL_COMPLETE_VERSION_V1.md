# Complete Cell version and publisher observation

Status: candidate byte-plane component; production, independent custody,
complete runtime adoption and FinalUse remain **HOLD_NO_GO**. This specification
is subordinate to the [sole development plan](../../TRNM_AI_NATIVE_BLOCKCHAIN_DEVELOPMENT_PLAN.md).

## Identity and complete declared coverage

TCV1 binds three previously separate objects in one canonical encoding:

1. The complete TMR1 model root, including TCD1 file names, roles, dependency
   edges, selected generation, loader profile, router roster and direct lineage.
2. One complete TCD1 environment inventory. The model context's `runtime` equals
   this environment closure's ID. Its files use the existing Configuration data
   role: executable images, libraries, settings and device/ABI descriptions are
   bytes to inspect, not instructions to run a dynamic loader.
3. Every complete TCM1 in the exact union of those two closures, in increasing
   manifest-ID order, including file length, whole-payload digest and all chunk
   lengths/digests. Missing, duplicate, foreign or noncanonical entries refuse.

The environment and model share the family, but keep their own original context,
generation and independently selected loader profile. There is no recursive hash
cycle: the environment uses its owner's environment-inspection context; the
model points to the resulting environment closure.

The actual loader owner must inventory every required dependency. This format
checks the declared graph and actual declared bytes. It cannot discover an
unlisted library, prove a device matches a description, prove a tensor ABI or
establish that loading the declared model succeeds. Those require the ordinary
loader's restricted dependency resolution and actual runtime readback.

## Exact wire and bounds

All integers are unsigned big endian. `frame(x)` is `u32(len(x)) || x`.

```text
TCV1 || frame(TMR1) || frame(environment TCD1) || u16(manifest_count)
     || frame(TCM1[0]) || ... || frame(TCM1[n-1])
```

The whole envelope is at most 8 MiB and contains at most 512 manifests. Existing
TMR1, TCD1 and TCM1 bounds also apply. Readers reject truncation, unsupported
magic, impossible lengths and trailing bytes before constructing a valid value.
The commitment is SHA-512 over the literal domain
`TRNM/Cell/CompleteVersion/v1` followed by a zero byte and the entire TCV1 wire.

The independent Python framing fixture is generated by
`scripts/cell_complete_version_vector.py`. Rust checks its complete wire,
commitment, model-root and environment-closure identities. The generator does
not call the Rust encoder. Its synthetic bytes are not a model-execution result.

TCM1 still uses its existing SHA-256 payload and chunk digests. The SHA-512 outer
commitment does not strengthen those leaves to a claimed whole-system quantum
collision bound, replace CPQ1 full-content work, or qualify the whole chain.

## Publisher signature and current view

CPV3 is a fresh signature domain and magic. Its 200-byte statement contains:

| Field | Bytes |
| --- | ---: |
| `CPV3`, version 3, algorithm `0x65`, withdrawal bit, zero reserved byte | 8 |
| Network and parameter IDs | 64 |
| Complete TCV1 commitment | 64 |
| Pinned signer key ID | 32 |
| Key generation, release sequence, issue time and expiry | 32 |

The existing canonical ML-DSA-65 provider signs the statement preceded by the
literal `TRNM/Cell/CompleteVersion/ML-DSA-65/v3` domain and one zero byte. The
3,309-byte signature follows the statement. CPR2 remains a separate profile;
there is no magic rewrite, downgrade negotiation or legacy fallback.

Verification requires the actual owner's independently supplied network,
parameters, signer pin, key generation, release sequence, version commitment,
both loader contexts and current time. Initial validation refuses a withdrawn
statement. A retained observation refuses current key revocation, changed
sequence, generation, loader profile, model scope, version pin, tighter chunk
budget, expiry and times before the original `verified_at`. A
cached publisher observation rechecks that view on every `version_at` call. The
observation retains its original verification lower bound; it is not a durable
last-observed-time ledger. The actual owner must supply a fresh view and keep
its time and revocation history from rewinding.

A later withdrawal must reach the real owner and change its current sequence or
key-revocation view. Signing another withdrawn statement at the same sequence
does not notify or invalidate a previously retained observation by itself. This
API is not a publisher high-water ledger; the ordinary owner must enforce
non-reused sequences and hold its current authority guard.

`version_at` is a metadata observation. A copied old owner view is not fresh,
and a returned ordinary reference is not an execution capability. The real
Hepta owner must hold its authority/resource guard at each execution boundary.
Local revocation history must remain independent of chain reorganization.

## Actual complete-byte readback

`CellVersionManifestV1::verify_cached` first checks both owner contexts and the
combined declared payload/chunk budget. It then reads every actual TCM1 from
the cache and runs the existing complete payload verifier with the same original
absolute deadline. That path checks every chunk and the ordered whole-file hash.
The environment is included in the aggregate charge. Cache repair waits do not
receive a fresh default deadline, and metadata hashing finishes before the final
deadline check. A completion marker or a successful signature is insufficient.

This bounded readback uses the real cache but grants no installation, CURRENT,
storage payment, tensor architecture, VRAM residency or FinalUse. Public plaintext
already copied by another node cannot be recalled by key or use revocation.

## Task loading and remaining device gate

The related residency change checks incremental RAM and reference requirements
after the complete manifest pass and before payload transfer, inside the same
`NetworkFetchSession`. It does not create a fresh connection, response-byte or
time allowance. Shared resident chunk buffers are counted once; every file
mapping consumes a reference allowance.

`admit_local_working_set` requires all canonical task closures already resident
under explicit task limits. Its borrowed handle prevents safe-Rust eviction or
selection mutation while live. Hot reads have no cache path, peer or transport
argument, and cannot fall back to remote download. They retain the original
deadline, compare current loader pins, and latch observed cancellation/expiry.
The admission deadline does not preempt arbitrary consumer computation.

Actual storage-device identity, NVMe transfer performance, GPU/VRAM allocation,
device readback and the ordinary Hepta expert path remain separate measured
gates. No fixture boolean stands in for those effects.

## External protocol context

The [retained-version recovery extension](CELL_RETAINED_RECOVERY_V1.md) checks
an exact owner-pinned set of current TCV1 promises, acquires their complete
model/environment union under one original network reservation, and keeps
conditional fault-domain analysis separate from actual byte reconstruction.
It does not change this TCV1 encoding or the meaning of a loader observation.

[IPFS persistence documentation](https://docs.ipfs.tech/concepts/persistence/)
distinguishes caching, pinning and the party that continues paying for storage.
[BEP52](https://www.bittorrent.org/beps/bep_0052.html) specifies file piece roots
and content transfer; it does not supply this release's long-term custody,
funding or execution permission. Neither protocol substitutes for the complete
version, custody or current-owner contracts above.
