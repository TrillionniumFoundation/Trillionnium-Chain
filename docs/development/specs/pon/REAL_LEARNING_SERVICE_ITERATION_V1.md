The inherited runtime's `prepare_plan` / `execute_plan` split preserves its
existing child and supervisor. The new operation entry calls that implementation;
it does not substitute a receipt-only worker. The original research CLI is still
explicitly outside the new cooperative once-only guarantee.

The composition driver requires a new private output directory and an explicit
SHA256-pinned native ELF. On Linux it executes a sealed snapshot of those ELF
bytes. It retains each process invocation before dispatch, the original standard
output/error, exit status and output hashes. A fresh `query` process calls only
the original provider, evaluator and native query entries. It does not resume a
partly completed run or reconstruct a missing authority.

The next input and its optional expected decoded-output SHA256 are fixed before
the main training starts. A complete numerical NoUpdate retains the exact
parent. Before starting the development inference, the driver requires a fresh
bound native query showing current-branch payment and no local revocation.
Unknown, missing or revoked observations keep the new operation blocked. This
checks the latest observation; it is not an atomic revocation transaction across
the independent model and native owners. A missing expected answer remains
unchecked, and a mismatched expected result remains a mismatch. A numerical
Candidate stops at the original-owner selection boundary. The driver does not
install it or treat an evaluator's result as permission to do so.

## Freeze before training

`hepta-smollm-frozen-evaluation-profile-v1` binds the original operation, complete
parent descriptor, training input SHA256, held-out input SHA256, source closure,
runtime recipes, steps, thread count, role roster, budget ceilings, scoring rule
and a positive integer improvement threshold. The profile carries no held-out
targets. `train` receives the training file and the held-out commitment;
`evaluate` receives the held-out file after all artifacts have been fixed.

The original operation journal stores the complete raw freeze and its SHA256
before it grants the single dispatch. Changing a profile, output directory,
input, parent, step count, operation or intent cannot resume an old reservation.
The evaluator refuses overlapping training/held-out prompt bytes and incomplete
or changed input sets. Shared local execution does not establish independent
custody: a separately controlled evaluator and original owner acceptance are
still required for that claim.

The comparison includes the actual retained parent, the inherited candidate,
the original immutable backbone, fresh budget-matched LoRA, budget-matched full
tuning and randomized rank-matched LoRA. The four existing control executors
actually run. Each role has the same declared ceiling for its phase. The three
optimized roles must report matching steps and aggregate input/supervised token
counts. These are incremental trial budgets; the historical cost of producing
the parent is not newly measured, and an ordered per-step token trace is not
claimed. The controls keep their predeclared initializations, including fresh
backbone controls; they are not relabeled as having all inherited the parent.

The candidate must exceed both the retained parent and the strongest control by
the frozen threshold. A completed comparison can report numerical `Candidate`
or `NoUpdate`. Missing, failed, over-budget or unresolved controls produce no
NoUpdate verdict. Neither numerical result changes `CURRENT`, signs an owner
selection, authorizes a bonus or adds chainwork.

## Original operation and Unknown

The new SQLite namespace uses an authority identity and unique constraints on
the operation, intent and output directory. Its reservation is fully committed
before output creation or process dispatch. Two cooperating processes cannot
both acquire it. A crash between reservation and spawn remains ambiguous and
does not grant a retry. `query` only reads the original output; it does not run
the model or supervisor.

Success readback requires the exact plan, original supervised exit and cleanup,
receipt identities, parent generation/contract, actual loaded-parent identity,
and the complete candidate manifests and safetensors bytes. Parent verification
uses the same captured bytes that are hashed into the terminal record. Inference
also checks the original request/response identities, model, role, snapshot,
fixed generated-token count and output digest. Its source operation must have
completed training under the same freeze, and its model must be the retained
parent or that source's exact produced descendant. This is execution lineage,
not permission to select or install a model.

Terminal file changes are rejected. Missing supervisor evidence, unresolved
owned-process cleanup or missing output stays `UNKNOWN`. A failed execution is
`FAILED`, never NoUpdate. Every readback retains the resource reservation;
only the original resource/settlement owner can reconcile it. Recreating or
rewinding the entire authority remains outside this local journal guarantee.

## Base service fee, improvement bonus and consensus credit

The native example creates a fresh development Node with the existing signed
TSC1 contract, escrow and M12 owner. `prepare` fixes the exact execution plan,
provider authority, original operation, complete output scope, CPU/parameter
caps, evaluation-profile commitment and base service fee before dispatch.

`settle` accepts only the original operation's retained readback and files. It
uses the existing `record_costs`, completion, delivery and payment owners. A
completed commissioned training service can receive its contracted base fee
with economic `NoGain`, without claiming an independently accepted model
improvement. The arithmetic and balances are actual development-ledger effects;
the local development keys and units do not represent independent customers or
real funds. Improvement bonus and consensus credit remain zero.

Unknown execution does not become an immutable final Unknown cost record merely
because a network acknowledgement is absent. The operation remains begun with
its full cap retained until authoritative readback resolves it. If required cost
observations are absent, no complete cost or payment qualification is inferred.
CPU, wall time and peak RSS are retained with their actual observation scopes.
This is not a complete bill for preparation, independent evaluation, network,
storage, repair, installation or later use.

Native side-effect intents are durable before admission. Cold recovery queries
the original packet/wire identity; an absent or uncertain observation does not
authorize resubmission. Current-branch payment membership is distinct from the
monotonic local history that a payment was observed. A chain reorganization
cannot erase the operation fence or create a new execution allowance. A local
revocation is durably retained before further reconciliation and prevents new
delivery/payment dispatch; it does not claim to stop a remote worker or undo an
already committed effect.

The additive recovery probe binds the existing native round's exact identity,
service intent, operation, original request and original payment packet. It
shares that round's exclusive lock and cannot create a replacement owner. A
phase records its immutable intent and each packet before a single admission;
an existing intent permits query only, including after an interrupted phase.
The competing fork has strictly greater original chainwork. Restoration extends
the original paid branch with empty maintenance blocks, without submitting a
new service delivery, payment, model result or execution.

For every successful phase, the original Node records the active anchor through
its existing reconciliation API. Cold query checks the retained Node history's
tip, state root, height, generation, operation binding and unchanged M12
checkpoint; a locally written completion file alone cannot certify historical
activation. Restore intent, packet ancestry and completion bytes are checked
before restoration. Local revocation remains in force when the old paid branch
returns. The ordinary block subsidy and reward queue follow the existing
protocol and are reported separately from the unchanged service fee, zero
learning bonus and zero useful-work consensus credit. This is a controlled
development fork exercise, not evidence of independent provider custody or a
production recovery acceptance.
