# Selected-event 合法算法与受限最优成本：本轮实质增量

**结论：在完全不修改 PR783 关系、输入、target 或旧 witness 的情况下，新增了更便宜的合法算术实现，并给出一个明确封闭策略类内的精确最优成本及有限预算下界。普遍物理工作成本门槛仍未关闭。**

基线是 PR783 head `3bbd072e4983eceee4531d7576d329da5b0d0900` 对应的 `round2_selected_composition`。`upstream/` 是本地37个文件的逐字节快照，来源与每个 SHA 由 [UPSTREAM_SOURCE.json](UPSTREAM_SOURCE.json) 固定。原参考关系 SHA 为 `39575219c2adf0cf73bc58f58acf8ede934d073cbb0a02fc552d9dd4f5963357`。快照中的旧21项检查与旧 native 结果仅为来源记录，不计入本轮新验证。

PR785 已说明合法 SHA 前缀复用与每张新票可零 fresh neural contraction。本轮增量针对现有非零 structured 输入上的明确算法、延迟缓存、筛选成本和受限最优策略，详见 [THEOREMS.md](THEOREMS.md)。

## 1. 未更换输入的合法结构算法

原始 `structured-a.bin`、`structured-b.bin` 的每个8×8块都满足

\[
A_{rt}=a_0+a_r r+a_c t,\quad B_{tc}=b_0+b_r t+b_c c\pmod q,
\qquad q=4294967291.
\]

`frontier.py` 先逐项检查全部8,192个域元素，只有精确满足该结构才编译。它拒绝非仿射块与非规范域元素。输入由两棵原有 Merkle 树认证；域、任务与 witness 格式完全沿用原参考实现。

| 阶段 | 域乘法 | 域加法／减法 | 额外精确检查或保留载荷 |
|---|---:|---:|---|
| 识别并编译全部128块 | 448 | 8,512 | 8,192次域相等检查；2,048字节参数载荷 |
| 每个新的有用8×8乘积 | **5** | **71** | 256字节输出 |
| 原普通8×8乘积 | 512 | 448 | 同一256字节输出 |

识别准备费用已计入实际 campaign 总数。源矩阵32,768字节、树摘要8,128字节及 Python 对象开销另有明确边界；上述载荷不冒充 RSS、DRAM 流量或物理内存下界。所有常量乘法也计为乘法。

这是该精确输入族上的可达资源上界。它不能外推到任意稠密输入，更不能证明5次乘法是普遍最优。对这组固定输入还可能继续作常量专门化；本轮没有把自身实现假定为最便宜。

## 2. 完整有限 campaign 已重放

七种策略各重放相同的 nonce 0…511。其余六种策略的完整1,419字节 witness 分别对 dense direct 基线逐字节比较，共3,072次比较；event 与 ticket 也一致。共有3,584次候选生成；每个 nonce 的规范结果（包括全部失败）保留在 [candidate_rows.json](results/candidate_rows.json)，七种策略共用经相等检查的这512行。六个 target 命中 nonce 为 **24、45、57、170、300、407**，每种策略对它们执行原完整 verifier，共42次新的完整接受复放。旧 nonce24 witness 原样重现。

512次选择出现323个不同坐标。以下总数包括准备、所有失败候选和实际发生的缓存失配：

| 策略 | 45个 nonce 的总乘法 | 总加／减法 | 512个 nonce 的总乘法 | 总加／减法 | 512个 nonce 的 useful 计算次数 |
|---|---:|---:|---:|---:|---:|
| dense direct | 92,160 | 86,400 | 1,048,576 | 983,040 | 512 |
| dense eager 全512项 | 331,264 | 295,616 | 1,048,576 | 983,040 | 512 |
| dense lazy 全容量 | 91,136 | 85,504 | 951,808 | 898,368 | 323 |
| dense lazy 容量16 | 91,648 | 85,952 | 1,037,312 | 973,184 | 490 |
| affine direct | 69,793 | 77,947 | 789,440 | 798,528 | 512 |
| affine lazy 全容量 | **69,783** | **77,805** | **788,495** | **785,109** | 323 |
| affine eager 全512项 | 72,128 | 111,104 | 789,440 | 798,528 | 512 |

原有 PRICING 的“预先计算全部512项与 direct 在512次时持平”是那两种算法的正确比较。新增 lazy 算法说明这个交点并非所有合法缓存算法都必须等待的门槛：只要同一任务坐标重复，lazy 就可以少做 useful 算术；lookup、载荷保存等仍须按实际资源模型定价。

这次同时对所有实际 SHA 消息重新执行了上游有界前缀实现，并逐摘要对照 `hashlib`。全部策略的消息序列相同。整段 SHA compression 数为准备894次，含第1、45、128、512个 nonce 分别为951、3,019、6,920、24,968次。它重新核验了现有合法前缀算法，没有声称新的具体 SHA 安全下界。本有限样本所有 sampler 都走 J=32 分支；没有把它提升成任意输入、任意次数的重试保证。

机器可读全量结果见 [frontier_result.json](results/frontier_result.json)。本轮没有运行 native 性能基准或生产 Node。

## 3. 受限类内的精确最优策略与下界

[selector_policy.py](selector_policy.py) 定义一个显式辅助模型：D个等概率独立坐标、每次实际尝试独立中奖概率p、固定选择器成本g、固定继续成本c、未缓存 useful 成本u、容量B；lookup与insertion均可设非负价格。所有被丢弃的选择器也付费。允许根据全部历史随机化，在每次选择后跳过、尝试不存储、或尝试并存储。允许免费外部提示、额外算法、提前预取等操作的更大类不在此最优性定理中。

Bellman 方程完全用 `Fraction` 求解，覆盖该类全部历史相关与随机策略。有限版本最多消耗n次选择器抽样，允许提前停止，分别返回期望成本和失败概率。它给出

\[
V_{n,\lambda}=\min_\pi\{\mathbb E C_\pi+\lambda\Pr[\text{失败}]\},\qquad
\mathbb E C_\pi\ge V_{n,\lambda}-\lambda(1-\alpha)
\]

作为任何成功率至少α的该类策略的成本下界。后一句是受限模型中的严格下界，不需要把真实 nonce 空间假装成无限；也不声称任意α都可达。

### 可审查的具体定价例

仅为展示算法，令1次 compression 与1次域乘法各价格1，其余价格0。取 D=512、p=1/64、g=3、c=1,580、dense useful u=512。这把观察到的 J=32 单次路径映射成常量费用，**并未对真实 sampler 的尾部、具体 SHA 独立性、设备或市场价格作安全假设证明**。

容量16时，最优可达策略先保存前15个不同的 useful 结果，之后跳过所有未缓存坐标。此前所有失败、未存储候选和筛选都收费。相比无缓存的辅助模型总价134,080，其准备后最优期望价为113,205.562426…；从新任务起算，两者还应分别加相同的904初始化价格，即 **134,984 对114,109.562426…**。

此904由两树894次压缩及首个 nonce 额外10次 context／prefix 开销组成。真正部署的解析、缓存、等待、分配、I/O等费用不能使用本例中的零价。

更关键的是：同一示例价格下，已验证的 **affine direct** 新任务价格仅为 **102,984**，包括448次编译乘法与904初始化压缩。它比 dense-cache 类的精确最优值还小。这是“某一封闭计算类的最优下界不能冒充所有合法实现的下界”的具体可执行证据。

在容量16、λ=250,000的有限模型中，程序还给出以下准备后下界；新任务均需加相同904初始化价：

| 选择器抽样上限n | 要求成功率α | 该受限类内期望成本下界 |
|---|---:|---:|
| 45 | 1/2 | 65,754.049957… |
| 128 | 17/20 | 111,261.755014… |
| 512 | 99/100 | 129,576.342059… |

这些下界由弱对偶直接证明，未声称是每个指定α的紧界。精确分子、分母、所选 penalty 的最优成本与失败概率均保存在 [policy_result.json](results/policy_result.json)。

## 4. 复现与验收边界

需要 Python 3.10+ 与标准库。在此目录运行：

```bash
python3 -B run_checks.py
```

入口实际运行本轮24个 unittest，然后重做七策略 campaign，核对原件 SHA，并写出 [checks_summary.json](checks_summary.json)、日志和新 `SHA256SUMS`。上游保留的21项旧检查不会被重复计为新证据。新增验证包括全部512个产品、模数回绕、非仿射和非规范拒绝、完整旧见证、有限缓存失配计费、独立坐标级历史搜索、穷举小状态策略与有限成功率对偶的紧例。

当前增量明确留下的缺口是：更广算法类、复杂物理模型、批处理与跨任务共享、设备／内存／带宽计价、任意输入上的任务难度、实际 SHA/QROM组合、生产全局资源控制与 Node 资格。具体新 profile Node 接入仍缺的实际运行项列在 [NODE_ACCEPTANCE_MINIMUM.md](NODE_ACCEPTANCE_MINIMUM.md)。**未授权任何生产激活；资格仍为 HOLD_NO_GO。**
