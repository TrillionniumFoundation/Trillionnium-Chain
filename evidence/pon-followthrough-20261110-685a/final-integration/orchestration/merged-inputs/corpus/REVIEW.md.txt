# Corpus union for the actual selected-parent + df927 merge

This is a local source-preparation helper. It has not run on the live checkout,
created a merge, executed native tests, or established acceptance of a merged
revision. The original C2 node full-suite failure and the subsequently observed
C3 integration failures remain distinct observations of those exact commits.
No source binding, test output, budget, assertion, ignored test, old evidence,
or frozen v1/v2/v3 integration input is rewritten by this helper.

## Invocation and retained artifacts

All paths below are caller-supplied absolute paths. This helper never starts a
merge, repairs the index, modifies checkout files, stages files, commits, fetches,
pushes, or runs the project tests. The caller performs the ordinary merge and
resolves the explicitly reviewed sources first. All content conflicts must be
resolved and staged; the corpus must temporarily be the exact first-parent
version. There must be no unstaged tracked change, untracked nonignored file,
sparse checkout, hidden index flag, or unresolved stage. `HEAD` must equal the
selected first parent and `MERGE_HEAD` must contain exactly df927.

```bash
python3 -B /absolute/path/prepare_union_corpus.py prepare \
  --root "$PON_MERGE_ROOT" \
  --binding-child "$PON_C3" \
  --ours "$PON_FIRST_PARENT" \
  --theirs df927b6ffaecff293b9e9428e3ba516f47cd101a \
  --candidate-tree "$PON_ACTUAL_STAGED_TREE" \
  --output "$PON_NEW_PREPARATION_OUTPUT"
```

`PON_ACTUAL_STAGED_TREE` is the real result of `git write-tree` after the source
resolutions and the inventory regeneration. For the currently planned direct
merge from the failed C3, `PON_FIRST_PARENT` and `PON_C3` are the same actual SHA.
No successful C3/C4 summary is required or manufactured.

The fresh external output contains exactly seven files:

1. `base-corpus.json`: exact original base bytes.
2. `ours-parent-corpus.json`: exact first-parent bytes.
3. `theirs-df927-corpus.json`: exact second-parent bytes.
4. `merged-corpus.json`: candidate with preserved fields and live staged pins.
5. `corpus-update.patch`: exact reviewed replacement of the first-parent JSON.
6. `review.json`: both pin deltas, actual resolutions and changed entries, source
   objects, selected ancestry, descriptor-read hashes, and explicit scope limits.
7. `receipt.json`: original and generated file lengths, SHA-256 hashes, Git blobs,
   helper identity, original staged-tree identity, parent identities and order.

Outputs are create-only. Existing receipts are never overwritten. Actual files
are opened with nonblocking descriptors and without following ancestor or leaf
symlinks, checked as regular files, hashed through Git, and rechecked for size,
mode, identity, and replacement. The stage and merge parents are rechecked after
all reads. The retained pin closure includes all 1,103 paths, including unchanged
historical pins, rather than only the changed values.

The caller can review and apply only `corpus-update.patch`, stage only the corpus
path, and complete a normal two-parent commit. There must be no additional tree
change between preparation and that commit. The separate verification command
then checks the actual merge:

```bash
python3 -B /absolute/path/prepare_union_corpus.py verify \
  --root "$PON_MERGE_ROOT" \
  --prepared "$PON_NEW_PREPARATION_OUTPUT" \
  --receipt-sha256 "$PON_PREPARATION_RECEIPT_SHA256" \
  --merge "$PON_ACTUAL_MERGE_COMMIT" \
  --output "$PON_NEW_VERIFICATION_OUTPUT"
```

Verification requires a clean actual merge HEAD with raw parents exactly
`[first parent, df927]`. Its tree must match the prepared staged tree at every
path except the exact generated corpus replacement. All 1,103 pins are checked
against the real merge tree and current file bytes. The output is a separate
`source-binding-verification.json` that asserts source binding only.
