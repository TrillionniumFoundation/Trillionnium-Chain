## Implemented boundary

The [existing post-write owner](../../trillionnium/crates/trnm-pon-node/src/store/native_authenticated/post_write_readback.rs)
still permits only child, genesis, the verified child's parent and the actual
active tip. A current Record can share an already verified account graph only
when its complete `Root { node, digest, count, balance }` matches in the same
connection, transaction, no-write epoch, schema and parameter context.

Every lookup remains after actual current Record, block, delta and complete-State
verification. Current nonce, account existence, parser grammar, working state
and reward liabilities retain their complete checks. Callback writes, transaction
replacement and cancellation retain the existing final fences. No receipt is
stored across transactions, and a fifth block cannot acquire eligibility from a
matching root. The [storage contract](../../docs/protocol/pon-nakamoto-v1/details/NATIVE_AUTHENTICATED_STORAGE_V1.md)
describes the remaining full-State/history costs.

The original first F0 round can save six large parent-graph traversals on its six
empty confirmation blocks. Its transfer block and nine distinct activation
transactions still perform their original required first traversals. This is a
source-path work-count deduction, not a measured end-to-end speedup. Reward
maturity also changes account roots even in some later empty blocks.
