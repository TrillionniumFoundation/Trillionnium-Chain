## What the kit does

* Requires an exact Git HEAD and clean worktree for release evidence.
* Generates review leads for Ed25519, ECDSA, secp256k1, Schnorr, RSA, Groth16 and BN254 occurrences. **Occurrences are not classified as deployed vulnerabilities**; each must be dispositioned with matching, tracked evidence before a release claim.
* Requires all 15 pre-seeded critical authorization routes to be verified as `pq-only`, `hybrid-and`, or **proven** `inactive` (no live authority). `hybrid-or` is always rejected.
* Checks role and chain binding, replay, epoch/version, signed-message downgrade resistance, rollback and classic-only negative tests.
* Checks that an unqualified W1 candidate **cannot** be active. An inactive unqualified prototype is a warning, not proof that the currently deployed consensus is insecure. The live consensus backend requires independent evidence.
* Requires an independently bounded quantum proof soundness claim for the **live** proof composition, separate from PoN mining economics.
* Requires cheapest-legal-solver / quantum cost review, external monotonic rollback anchoring, and resource/DoS evidence.
* Validates SHA-256 digests of evidence artifacts inside the repository and ensures they are tracked by the pinned commit in release mode.

## Run

Python 3.10+ required; no package dependencies.

```bash
# From this kit's directory. Replace /path/to/Trillionnium-Chain.
python3 -m unittest discover -s tests -v

python3 tools/pq_audit.py \
  --repo /path/to/Trillionnium-Chain \
  --policy policy/pq_policy.json \
  --evidence examples/pq_evidence_UNREVIEWED.json \
  --mode scan \
  --out /tmp/trnm-pq-scan.json
```

`--mode scan` enumerates candidates and evaluates evidence completeness; it is expected to say `BLOCKED` with the supplied placeholder evidence. Read the full JSON report, including `classic_crypto_review_leads.hits[].fingerprint`, and do not call any unreviewed occurrence a production vulnerability.

To prepare a release-gate run, add properly reviewed evidence artifacts **to the repository and commit them**. Only *after* source and artifacts are frozen, copy the placeholder evidence JSON **outside the repository**, fill `source_commit` with `git rev-parse HEAD`, use artifact-relative paths with `sha256` hashes, and independently review every listed source finding. Set a route to `inactive` only if its lack of live authority has been independently verified.

```bash
python3 tools/pq_audit.py \
  --repo /path/to/Trillionnium-Chain \
  --policy policy/pq_policy.json \
  --evidence /outside/repo/pq_evidence_FOR_FROZEN_SHA.json \
  --mode release \
  --out /tmp/trnm-pq-release.json
```

The CLI returns exit code `1` if any mandatory blocker exists, `2` for input errors, or `0` when machine-checkable evidence metadata is complete. Even exit `0` means **`METADATA_READY_INDEPENDENT_SECURITY_REVIEW_STILL_REQUIRED`**, not that crypto security has been proven. Audit statements in metadata are human assertions; SHA-256 artifact integrity is not proof of those assertions' truth. Independent cryptographers and production replay tests must approve any claim.

## Layout

- `tools/pq_audit.py`: runnable evidence validator and source-use heuristic scanner.
- `policy/pq_policy.json`: required roles, candidate W1 manifest path, and adversarial solver classes.
- `examples/pq_evidence_UNREVIEWED.json`: explicitly **unqualified** starting evidence, all gates blocked.
- `tests/test_pq_audit.py`: standalone synthetic tests of the validator (not chain tests).
- `docs/THREAT_MODEL.md`: protocol threats, trust roots and cryptographic boundaries.
- `docs/ENGINEERING_PLAN.md`: concrete module-by-module migration and acceptance criteria.

## Constraints

1. Does not verify ML-DSA signatures, proofs, STARK soundness, or quantum gate counts.
2. Does not follow dynamic authority/control flows or prove complete code coverage; manual source tracing remains required.
3. `classic_crypto_review_leads` is a heuristic list, not a static taint proof. Comment/test-only signatures can be marked `test_only` / `non_authoritative` with evidence.
4. Does not handle runtime activation, and has not exercised a real Trillionnium node.
5. Must be integrated and evaluated against a current cloned HEAD before it can block a real release.
