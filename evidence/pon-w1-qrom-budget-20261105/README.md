# W1 locked component budgets and remaining QROM premise

This evidence closes the **numerical reproduction** of the selected backend's
component error formulas. It does not qualify a complete W1 proof or establish
an attack. The primary result is [component-budget.json](component-budget.json),
generated by [w1_security_budget.py](../../scripts/w1_security_budget.py).

The explicit comparison is a **research failure-probability budget of `2^-128`**.
It is not an adopted protocol policy or a claim about an adversary's quantum
work factor. The repository has not supplied the quantum query budget or a
complete instantiated theorem needed to connect those two notions.

## Reproduced source and equations

The tool checks four exact `.crate` archives against both the hardened verifier's
Cargo.lock and immutable expected SHA-256 values. It then hashes ten selected
source members. This extends the earlier [source map](../pon-w1-transparent-profile-20261104/security-map.json)
with the RV32IM tap set and the tap accessor needed to calculate register counts.
The [source commit](https://github.com/risc0/risc0/tree/8c215e2f4ccdd935f0517bf05d90f1ae032840a9)
is the commit recorded for those packages. No source or verifier parameter is
modified by the calculator.

| Item | Exact selection |
| --- | --- |
| STARK library | `risc0-zkp 3.0.5` |
| Base field implementation | `risc0-core 3.0.2` |
| Circuit tap sets | `risc0-circuit-rv32im 4.0.5`, `risc0-circuit-recursion 4.0.5` |
| Base modulus `p` | `2013265921` |
| Extension degree `e` | `4`; challenge-field cardinality `p^4` |
| Rate / queries / fold / stopping degree | `1/4`, `50`, `16`, `256` |
| RV32IM registers | accum `103`, code `1`, data `211`; total `315` |
| Recursion registers | accum `12`, code `23`, data `128`; total `163` |
| Largest tap combination | `6` for both selected circuits |
| Constraint degree | `5`, hard-coded by upstream's calculator; not an independent proof for every program |

For trace rows `n = 2^po2`, accumulator width `w`, and queries `q`, the upstream
[Toy Model formula](https://github.com/risc0/risc0/blob/8c215e2f4ccdd935f0517bf05d90f1ae032840a9/risc0/zkp/src/prove/soundness.rs)
is evaluated as:

```text
E_lookup = (w / 4) * 3 * n / p^4
E_constraints = 1 / p^4
E_queries = (1 / 4)^q
E_toy = E_lookup + E_constraints + E_queries
```

The tool separately evaluates upstream's `proven` list-decoding formula,
including proximity, folding, query, DEEP and ALI terms. It does not evaluate the
`conjectured_strict` path with unspecified conjecture constants. The query term
in the selected list-decoding path is `(33/64)^q`, not `(1/4)^q`.

All budget comparisons use exact rational arithmetic. The irrational square
root in the list-decoding expression is enclosed by rationals with 128
fractional bits; the chosen endpoint rounds the error expression **upwards**.
Displayed logarithms are descriptive only. This evaluates the mathematical
expressions independently of upstream's `f32` rounding.

## Concrete parameter decision

The selected formulas cannot certify the `2^-128` research budget. That is a
failure of the available certification evidence, not a proof that the complete
construction has an attack at the corresponding cost.

1. With 50 queries, the Toy Model query term alone is exactly `2^-100`.
2. With 64 queries it is exactly `2^-128`; the positive remaining terms make the
   sum larger. At least 65 queries is therefore only a necessary query-term
   condition for this particular budget.
3. The fixed lookup and constraint terms already exceed `2^-128`. Increasing
   queries alone cannot make the Toy expression meet the budget. Even the term
   `1/p^4` exceeds it, since `log2(p^4) = 123.6275623853`.
4. The selected list-decoding formula also has positive proximity/folding terms
   independent of queries. Its recorded subtotal already exceeds the budget
   for every emitted circuit/trace-size row.

Changing the challenge field, AIR, rate, degree assumptions or proof repetition
requires a fresh construction and composition argument, fresh control roots and
receipts, and new cost measurements. The tool does not produce a replacement
parameter set or change the accepted profile. In particular, it does not label
`queries=65` or a larger field as sufficient.

## Exact hash/sampling arithmetic, with its premise explicit

The pinned [Poseidon2 implementation](https://github.com/risc0/risc0/blob/8c215e2f4ccdd935f0517bf05d90f1ae032840a9/risc0/zkp/src/core/hash/poseidon2/mod.rs)
uses eight canonical BabyBear elements for a digest. Its valid digest codomain
has cardinality `p^8`, or about `247.255125` bits, although its stored encoding
occupies 256 bits. Those are different quantities. This does not establish a
collision attack on the complete proof, and the tool does not assign a QROM
oracle-output parameter to the concrete hash.

The pinned [RNG](https://github.com/risc0/risc0/blob/8c215e2f4ccdd935f0517bf05d90f1ae032840a9/risc0/zkp/src/core/hash/poseidon2/rng.rs)
selects the first nonzero value among four draws, keeps zero if all four are
zero, and masks low bits. In the explicitly hypothetical experiment where the
four field draws are independent and uniform, its distance from uniform `b`-bit
output is exactly:

```text
TV = (1 - 2^-b) / p^4       for 1 <= b <= 27
```

The derivation uses `p-1 = 15 * 2^27`: conditional on a nonzero selected word,
all low-bit residues have the same number of preimages. The all-zero event has
probability `p^-4` and adds mass at zero. A test exhaustively enumerates all
`17^4 = 83,521` four-word tuples of a smaller analogous domain and checks the
exact distribution. FRI's source-wide maximum index width is 26 bits.

This closes that idealized sampler's arithmetic, **not** the claim that an
adaptive concrete Poseidon2 transcript supplies independent uniform field
draws. A complete transcript/hybrid/query budget is absent and remains `null`.

## QROM paper review boundary

[theorem-review.json](theorem-review.json) distinguishes author/publication
metadata, introduction-level indexed statements, the author's slide deck, and
formal full-text access. The ePrint metadata identifies a March 2, 2026 revision;
the separately indexed manuscript introduction is dated January 1, 2026. Their
full-text equality has not been checked. PDF retrieval from ePrint and the CORE
mirror returned HTTP 403, and the publisher page exposed subscription preview
content. The retrieved author PDF is a 167-page slide deck, not the manuscript.

The [paper's public abstract](https://eprint.iacr.org/2025/2166) gives a conditional
BCS/IOR framework: post-quantum state-restoration plus suitable commitments;
round-by-round security can supply the former. The indexed introduction also
describes query-dependent losses for state restoration and Merkle extraction.
Those asymptotic statements are not concrete constants for this implementation.
No formal theorem premise or constant is marked discharged here.

The remaining material requirement is an actual bound for the exact AIR/IOR,
Fiat-Shamir sampling, hash/commitment interfaces, every accepted recursive
program and the full adaptive query/composition budget. Neither these numerical
results nor a generic hash-collision estimate supplies it. All quantum and
complete recursive security-bit fields therefore remain `null`; production and
consensus-admission flags remain `false`.

## Reproduction and validation

Obtain the four archives from their canonical crates.io package downloads:

- [risc0-zkp 3.0.5](https://static.crates.io/crates/risc0-zkp/risc0-zkp-3.0.5.crate)
- [risc0-core 3.0.2](https://static.crates.io/crates/risc0-core/risc0-core-3.0.2.crate)
- [risc0-circuit-recursion 4.0.5](https://static.crates.io/crates/risc0-circuit-recursion/risc0-circuit-recursion-4.0.5.crate)
- [risc0-circuit-rv32im 4.0.5](https://static.crates.io/crates/risc0-circuit-rv32im/risc0-circuit-rv32im-4.0.5.crate)

The tool performs no network requests and does not require Rust or unpacked
Cargo sources. Point it at a directory containing those files:

```bash
python scripts/w1_security_budget.py \
  --crate-cache /path/to/crate-cache \
  --target-bits 128 \
  --output /tmp/w1-component-budget.json
python scripts/ci/test_w1_security_budget.py
```

Exit zero means that the numerical report was reproduced. It does not mean
qualification: the report explicitly records the failed budget and the unknown
whole-proof and QROM quantities. Unsupported source, checksum drift and invalid
input return exit 2. The saved run passed all **21** regression tests, including
corrupt archive/lock rejection, exact boundary arithmetic, sampler enumeration,
and the rule that even a deliberately easy passing component budget cannot
upgrade whole-proof, production or quantum qualification.
