## 2. Hash framing and rejection sampling

For a SHA-256 input of L bytes, ordinary full evaluation requires

\[
C(L)=\lceil(L+9)/64\rceil
\]

compression evaluations. The extra bytes encode the initial padding bit and 64-bit bit length, with zeros to the next block boundary. This follows FIPS 180-4 §§5.1.1, 5.2.1 and 6.2 [P1]. The actual framed inputs are 361, 173, 163, 274, 95, 92, 98, 617 and 79 bytes for leaf, node, task, context, seed, selector, noise, event and ticket respectively; their ordinary compression counts are 6,3,3,5,2,2,2,10,2. The pinned source and `hash_length_table` derive these numbers from the real byte encoding.

`sha256_input_bytes` records semantic unpadded input bytes requested by calls. It is not DRAM traffic or bytes sent over a network. For ordinary full calls, padded compression input bytes are 64 times the compression count. Prefix reuse changes compression work without necessarily eliminating all framing or comparison work.

Let J be the number of noise digests used to obtain the 32 selected rows. For completed sampling, 32≤J≤4096. Every digest supplies eight uniform 32-bit candidate words, accepting values below q=4294967291. The exact probability all 32 rows finish using only counter zero is

\[
\left(\frac q{2^{32}}\right)^{256}.
\]

One row aborts iff fewer than eight candidates are accepted among 1024. Its exact probability is

\[
\sum_{j=0}^7\binom{1024}{j}
\left(\frac q{2^{32}}\right)^j
\left(\frac5{2^{32}}\right)^{1024-j}.
\]

`noise_abort_probability` computes this rational expression. The accepted values are uniform independently of the rejection pattern; therefore this is an availability/cost issue, not an approximate modulo-bias assumption in the security theorem. The implementation stops on budget exhaustion.

## 4. Full-output memoization

Task/context hash calls repeat identical inputs. They may be cached without changing the relation. One accepted verifier call requests 56 hashes but has 52 distinct inputs: 7,254 distinct input bytes and 136 ordinary full-hash compressions after output memoization. Replaying the same complete witness may allow still more cache reuse; the original 152 count is not a minimum.

For a fixed prepared task and context, the first producer trial has 38 new hash inputs and 88 full-hash compressions after complete-output caching. Later nonce trials have 36 new inputs and 80 full-hash compressions when J=32: seed, selector, 32 noise messages, event and ticket. Reusing task/context results removes four repeated calls per later trial from the ordinary 40-call schedule.

These optimizations preserve every seed, coordinate, path, D, U, event digest and ticket. They change when and how computation is performed, not which mathematical event is accepted.

## 5. Exact SHA prefix reuse, including bounded memory

All noise messages for one seed share their first 64 input bytes. Each 98-byte message normally uses two compressions. Compute the common first-block chaining state once and finish one second block per row/counter message:

\[
32\times2=64\quad\longrightarrow\quad1+32=33.
\]

For J distinct messages the count is J+1. `sha256_prefix.py` implements standard SHA-256 compression directly and matches every output against `hashlib`. This uses the original full hash values, not an approximation or altered hash.

Other common prefixes exist. Every leaf input shares one first block; every node input shares another. In the recovered fixed task, 128 leaves need 641 prefix-cached compressions, and 126 nodes need 253, for 894 total rather than 1,146. For one fixed context, seed and event first blocks remain constant across nonces. Their later blocks still bind the current nonce and event values.

There are two explicit cache implementations:

* **PrefixSHA256:** a diagnostic trie of every complete 64-byte prefix. This has growing history storage, which is recorded rather than treated as free.
* **BoundedPrefixSHA256:** at most five first-block state slots, for leaf, node, seed, event and current noise seed, plus two full-digest slots for task/context. Every slot compares its complete key before reuse and replaces the old entry on a miss. Even a wrong tag hint cannot alter a digest; it can only change cache reuse.

The bounded strategy evicts old seeds and contexts. Its cost example does not rely on retaining an unlimited history. A fresh 100-seed / 800-message check compares all results with `hashlib`, verifies 900 compressions and demonstrates stable one-slot noise-cache payload during that check.

## 6. Useful-product cache and arithmetic

For fixed committed A/B matrices, the 512 products `U_(i,k,j)=A_(i,k)B_(k,j)` do not depend on nonce or parent/context. Computing all of them with the plain algorithm costs 262,144 multiplications and 229,376 additions, with 131,072 bytes of result-table payload. Each nonce can then save one 8×8 product, i.e. 512 multiplications and 448 additions.

Both tested strategies pay the same trees. Raw matrix payload is 32,768 bytes, and two full Merkle trees contain 8,128 digest bytes. The cached producer's table is an additional allocation, not an assumed free property of the input.

For m trials, ignoring common work,

\[
M_{\rm direct}=2048m,\qquad M_{\rm cached}=262144+1536m.
\]

The multiplication totals meet at m=512 and the cached total becomes smaller at m=513. The same break-even holds for multiplication-plus-addition tariffs if both strategies use the same arithmetic algorithm and memory/read costs are zero. Positive preparation, storage-duration or lookup costs can delay or eliminate the advantage. This is compatible with the old native observation that caching was faster in only some short paired campaigns; this recovery does not retime those campaigns.

Zero, identity, low-rank or repeated inputs may allow cheaper useful products or preparation. Batching can expose further shared structure. The full 512-entry table is an achieved general strategy, not the minimum over all legal strategies. Reusing old U values also does not establish new useful economic demand.

For exact Strassen recursion depth d∈{0,1,2,3}, with leaf side a=8/2^d, the explicit seven-recursion/eighteen-block-addition schedule gives

\[
M_d=7^d a^3,\qquad
A_d=7^d a^2(a-1)+18\sum_{j=0}^{d-1}7^j(8/2^{j+1})^2.
\]

## 7. Explicit price vectors and the certified model boundary

A configurable resource bill can be

\[
\mathcal C=c_hN_{\rm calls}+c_bB_{\rm input}+c_cN_{\rm compress}
+c_mN_{\rm mult}+c_aN_{\rm add}+c_sS_{\rm retained},
\]

for nonnegative chosen prices. `Resources.priced` evaluates rational prices exactly. Calls, bytes and compression evaluations can overlap if they represent the same service; set unused terms to zero instead of silently charging the same work twice. Semantic hash-input bytes are not measured memory traffic. Memory rental requires a duration factor; one-time allocation should not be multiplied by each nonce. The cached arithmetic helper charges the table payload once.

An achieved whole-campaign upper bill must include preparation, misses, filters, discarded candidates, retained state and final verification if the payer performs it. Producer and receiver bills should be separate. A post-setup median or a verifier's operation count cannot prove producer minimum work.

For a lower statement, an independent oracle tariff may charge `c_row` for every distinct adversarial row access. Under the classical theorem and supplied tiny error budget, half success at p=1/64 requires at least 1,440 such accesses, so at least `1440 c_row` **by that tariff model**. The theorem gives no positive universal field-operation tariff. One cannot replace c_row by an unproved fixed number of SHA compression evaluations, hardware cycles or a measured median. The exact 64→33 noise-prefix optimization is a concrete reason why multiplying 32 row accesses by two ordinary hash blocks is not a physical lower-bound proof.
