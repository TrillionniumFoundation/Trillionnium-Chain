# Conditional sponge query arithmetic

This standard-library Python tool evaluates a conditional random-permutation
model. It produces **no concrete security certificate**, and `qualified` is
always `false`. It does not run or qualify a hash, Merkle tree, proof system or
consensus mechanism. SHA3-512 supplies only the default parameter shape
`r=576, c=1024, d=512`; the model still samples a uniform permutation.

## Run

Requires Python 3.10 or later and no packages:

```sh
python3 sponge_query_budget.py example_sha3_512.json
python3 -m unittest discover -s . -p 'test_*.py' -v
```

A request can also be supplied on stdin. Exit code 0 means conditional
arithmetic completed; exit code 2 means unsupported input. Neither means a
security gate passed. The example assumes a hypothetical total of `2**64`
swap queries, including precomputation. It is not an empirical resource limit.

## Arithmetic and supported game

The source is Carolan–Majenz, [*Compressed Permutation Oracles Revisited*,
arXiv:2609.28469v1](https://arxiv.org/html/2609.28469v1), Theorem 5.5,
equations (94)–(95), read 2026-11-08. With `b=r+c` and `T=q+2L`, the code uses:

| Event | Digest term | Capacity term | Permutation simulation term |
|---|---|---|---|
| Fixed-target preimage | `64*T**2 / 2**d` | `128*T**3 / 2**c` | `32768*T**2 / 2**b` |
| Collision | `32*T**3 / 2**d` | `128*T**3 / 2**c` | `32768*T**2 / 2**b` |

`L` bounds the total padded blocks in the candidate output: one message for a
preimage, both messages together for a collision. Each has a separate `T`.
The program requires `d <= r`, nonempty injective padding, injective message
encoding, first-block output, and a target fixed independently of the
permutation. It checks `16*T*T <= 2**b` and `3*T-1 <= 2**b` with integers.

Every term, its sum, and the sum clipped to 1 use `fractions.Fraction`.
Numerators and denominators are decimal strings. There is no floating-point
conversion, estimated security-bit field, or downward rounding. These are
the source's simplified bounds, not its tighter square-root expressions.

## One budget across the entire primitive

Every request explicitly includes leaf, branch, transcript and other buckets.
Each contains precomputation/online and forward/inverse upper bounds, including
explicit zeros. Additional named roles are permitted and added to the same
total. These are conservative budget buckets, not measured quantum-query
labels. A coherent query can superpose several roles or domains and need not
have any unique classical role. Charge the whole such query to `other`, or
count it in multiple buckets as an overestimate; never omit it or split it
into fractions. No independence of role oracles is assumed. The allocation
must upper-bound all calls to the shared primitive, and changing bucket labels
cannot reset its budget. The tests check this accounting, not a quantum
implementation. Unclassified uses also belong in `other`. The coverage declarations include
failed, aborted, offline and cross-session activity. They are **unverified
caller assumptions**. An honest-process measurement, incomplete ledger,
per-proof allowance or online-only budget is not an adversary upper bound and
is not a supported input basis.

Section 5 of the source states that one standard XOR query can be simulated
with two swap queries. Therefore `unit=standard_xor` converts the summed input
count to `q_swap=2*q_xor`. The additional `2L` is already measured in swap
queries and is not doubled. Hash calls are not permutation-query units; callers
must account for the actual primitive-query simulation of all interfaces.

The earliest state in the counted lifetime must be permutation-independent.
Correlations subsequently generated by the counted precomputation are allowed.
Unknown or free construction-dependent advice, whether classical or quantum,
and uncounted permutation-dependent side information are unsupported. The tool
does not prove that a real attacker satisfies those restrictions.

## Multiple fixed preimage targets

An optional enlargement is represented by `fixed_preimage_target_count` (use 1
for the single-target case). The complete target family must be fixed
independently of the permutation. Each event is bounded using the **same full
lifetime `q`**. The extra result is `min(1, target_count * single_target_sum)`.
This union bound does not assume independent success events and never divides
`q` among targets. It is not a method for converting a per-attempt allowance
into a lifetime bound. The collision event has no target multiplier.

## Input contract and unsupported claims

Use `example_sha3_512.json` as the complete schema. Only `parameters` may be
omitted; no model assumptions silently default. Counts may be JSON integers
or canonical decimal strings; strings avoid loss in external JSON clients.
Floats, scientific-notation numbers, duplicate JSON keys, missing coverage,
unknown fields and noncanonical integers are refused.

The following return `status=unsupported`, with no numeric bounds:

- fixed Keccak/Poseidon2, a field permutation, or an unspecified primitive;
- raw full-width permutation truncation, duplex/FS or multi-squeeze claims;
- unknown/free advice, incomplete query coverage or a non-lifetime budget;
- unbounded/missing message lengths, noninjective encoding or padding;
- adaptive/permutation-dependent preimage targets;
- parameters outside the supported theorem range.

The calculator does not certify the asserted injectivity or interface
simulation. Its collision game is not a theorem about MMCS openings, leaf and
branch encodings, extraction, recursion, or W1. Listing a transcript role merely
charges its permutation use to `q`; it grants no Fiat–Shamir guarantee.

Local resource limits are 128 KiB of JSON, 64 role buckets, 4096 total state
bits and 2048-bit count inputs. These limits protect this script and are not
cryptographic security limits. The source is a version-pinned preprint; this
implementation checks its arithmetic, not its proof.

## Related model boundaries

Alagic–Carolan–Majenz–Tokat, [*The Sponge is Quantum Indifferentiable*,
2025, Theorem 7.22](https://arxiv.org/html/2504.16887v2), supplies a quantum
ideal-permutation construction result. It does not identify a fixed Poseidon2
instance with the ideal primitive, nor does it alone supply this project's
shared-interface or Fiat–Shamir knowledge argument.

Carolan–Poremba–Zhandry, [*(Quantum) Indifferentiability and Pre-Computation*,
2024, Sections 4 and 8](https://arxiv.org/html/2410.16595v1), separates ordinary
substitution from preprocessing security. Its positive application concerns
a one-round sponge with `r <= c`. No advice tradeoff from that application is
used here. This tool instead requires the entire query-generating history to
be counted from a permutation-independent state.

[NIST FIPS 202](https://csrc.nist.gov/pubs/fips/202/final) specifies SHA3-512.
Using its parameter dimensions here is not a proof about the fixed Keccak
permutation. New profiles still require their own implementation and protocol
qualification.
