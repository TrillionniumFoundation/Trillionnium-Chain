## Critical replay-admission correction

The reviewed RW-10 fix closes three distinct cases: a revoked row changed during Current, a changed row restored before later root verification while a stale authorization read survives, and an internally consistent old checkpoint plus all protected rows restored after Current. The current client stores the complete authenticated external sequence/root in memory; transaction-local predecessor validation must match it. Every permission-bearing read for existing pending/Cached requests, retirement and revocation occurs under the same IMMEDIATE transaction. New insertion reuses its admission transaction. Two authored regression functions cover six pending/completed scenarios and assert that no new native packet or active-state effect is created. Both functions executed and passed in the first native witness suite.

The original one-step recovery contract remains separate: local checkpoint must equal the exact signed predecessor, replay must produce the exact successor root, actual Submit effect must survive and be read under the same write transaction, and a second Current must confirm the same head. It does not incorrectly require the predecessor to equal the successor before recovery.

## Compile-integration review

The earlier forbidden raw socket operations were replaced by the locked rustix safe owned-descriptor APIs. Connect remains nonblocking; poll uses only the original deadline remainder; backlog saturation/interruption refuses without an unbounded retry. Construction is explicitly Linux-only. Backend initializer and exhaustive-match fixes explicitly reject unsupported backend use; they add no legacy fallback. The integrator owns complete build/source-freeze provenance; this reviewer records the exact supplied binary and selected native runtime receipt below.

## Deadline and completion contract

Per root, charge/begin use the original absolute request deadline; Finish preserves original noncancellable result persistence with its separately bounded exchanges. ACK still uses the original socket deadline; finalization tail cost must be accounted separately.

## Explicit scope boundaries

- Only pq_network_resource_v2, pq_network_peer_v2 and pq_network_request_v2 are checkpointed. An equal protected checkpoint does not authenticate all account, History, journal, CURRENT, FinalUse or Cell state.
- The witness fixture fsyncs/renames a state file outside the Node directory, but starts authoritative State as None. It does not test witness-process cold reload, power failure, separate administration or deployed independence.
- The new SHA-512 application commitments and checkpoint root do not change inherited 32-byte policy/context/operation identifiers or supply a universal quantum-cost proof for those uses.
- Five-MiB witness frames and bounded protected-table scans do not establish hard preemption inside cryptographic or SQLite calls, sustained WAN service or original service-budget acceptance.
- A pure local pre-CAS callback refusal can recover in the same Node. Witness authentication/transport uncertainty remains fail-closed and requires a fresh client/reopen; this does not qualify broad outage recovery availability.
- More-than-one-step rollback, same-generation configuration rollback, service reset and cross-host fork safety depend on the externally protected binding and a correctly durable independent CAS service; no production service is supplied.
- The original operation-identity digest remains a protocol assumption. Complete retained-wire hashing in Finish prevents signature-retry mismatch but is not a redesign of all replay identifiers.
- Account migration, W1 quantum work cost, retarget/chain-selection safety, compressed-proof quantum soundness, WAN traffic, end-to-end capacity and whole-chain security remain unqualified.
- A fresh Current reply is an observation, not a distributed lease. Cross-operator cloned-credential concurrency and linearization remain outside this native single-owner qualification.
