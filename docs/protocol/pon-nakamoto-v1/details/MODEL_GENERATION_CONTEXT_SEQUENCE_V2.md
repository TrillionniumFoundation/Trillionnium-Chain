## Relation

`verify_context_bound_generation_sequence` in
`formal/pon-nakamoto-v1/model_generation_sequence.py` first executes the complete
V1 sequence verifier and the context-bound signed V2 consumer verifier. Both must
name the same verified signed decisions. Each supplied complete run plan must
project to exactly the task IDs, prompt hashes, source groups and partitions
retained by its exposure-history row. A mismatch is rejected with
`GENERATION_SEQUENCE_EXPOSURE_BINDING`.

This closes a composition/import consistency gap: independent acceptance of plan
identity and signed context alone does not compare actual plan exposure with the
history declaration. An internally rehashed and re-signed package may otherwise
state fresh history while the supplied plan repeats a previously evaluated prompt.
The normal exposure admission already projects plans. This additional check does
not break a trusted external history pin or replace its durable owner.
