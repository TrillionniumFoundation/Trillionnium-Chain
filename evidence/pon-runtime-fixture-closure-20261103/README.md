### What the diagnostic attachment establishes

The actual legacy `ROOT` error has no typed `ErrorCode`. Existing typed-code
fields therefore legitimately remain null for that legacy error. Adding `ROOT`
to the production error-code parser would also affect classifications used by
owner-stop and retry behavior. This patch keeps those semantics and stores an
independent diagnostic attachment containing the actual error kind, a bounded
96-byte UTF-8 prefix of the existing display text, and whether that prefix was
truncated. Dispatch and terminal diagnostics remain distinct when a later
cancellation or transport result differs from the dispatch error.

The existing 19 phase slots and wait shapes remain unchanged. The reader checks
the attachment version, field shapes, bounds and a narrow set of impossible
code/kind combinations. It preserves legal pre-dispatch errors, independent
display text, local-structure overrides and authenticated remote refusals.
These checks are neither a complete production ErrorCode registry nor proof of
the private owner-stop origin. Diagnostic text does not grant authorization,
