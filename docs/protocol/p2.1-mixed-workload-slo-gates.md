# P2.1 Mixed Workload SLO Gates

Date: 2026-02-19
Scope: `trillionnium-rust` nightly/release gate

## Purpose
把 mixed workload 基准从“可跑”升级为“可判定”，用于 nightly 与 RC 前硬门禁。

## Benchmark Profiles (fixed)

### Profile A — Mixed Balanced
- command:
```bash
cargo run -q -p trnm-bench -- \
  --workload mixed --txs 5000 --keys 1000 --read-fanout 3 --write-every 2 --profile
```
- target:
  - elapsed_ms <= 300 (warn), <= 600 (hard)

### Profile B — Mixed Write-heavy
- command:
```bash
cargo run -q -p trnm-bench -- \
  --workload mixed --txs 5000 --keys 500 --read-fanout 3 --write-every 1 --profile
```
- target:
  - elapsed_ms <= 300 (warn), <= 600 (hard)

### Profile C — Mixed Read-heavy
- command:
```bash
cargo run -q -p trnm-bench -- \
  --workload mixed --txs 5000 --keys 500 --read-fanout 3 --write-every 4 --profile
```
- target:
  - elapsed_ms <= 300 (warn), <= 600 (hard)

## Matrix Script
Use:
```bash
TXS=5000 ./scripts/run_bench_mixed_matrix.sh
```
Artifact pattern:
- `run/bench/bench-mixed-matrix-<timestamp>.txt`

## CI Gate Variables
In `.github/workflows/rust-l1-nightly-health.yml`:
- classic bench:
  - `BENCH_WARN_MS` (default 300)
  - `BENCH_MAX_MS` (default 600)
- mixed bench:
  - `BENCH_MIXED_WARN_MS` (default 300)
  - `BENCH_MIXED_MAX_MS` (default 600)

## Release Rule
RC requires all below in latest run:
1. `cargo test --workspace` pass
2. state root audit `ok=true mismatch=0 missing=0`
3. classic bench threshold pass
4. mixed bench threshold pass
5. `rust-l1-nightly-health` 连续 **3 次** success（同一主线分支）

## Strategy Experiment (non-gate, nightly artifact)
为 executor 第二轮优化增加实验轨（不阻断门禁）：

```bash
TXS=10000 KEYS=2000 READ_FANOUT=4 WRITE_EVERY=2 ./scripts/run_executor_strategy_experiment.sh
```

- 输出：`run/bench/executor-strategy-exp-<timestamp>.txt`
- 当前比较策略：`original` / `hot-bucket-interleave` / `auto-adaptive` / `aggressive-greedy`
- 用途：观察 mixed 负载下 `groups` 与 `elapsed_ms` 的变化趋势，验证 auto-adaptive 的收益与回退行为。

### Auto-adaptive 阈值扫描（non-gate）
```bash
TXS=5000 KEYS=1000 READ_FANOUT=4 WRITE_EVERY=2 ./scripts/run_auto_adaptive_threshold_sweep.sh
```
- 输出：`run/bench/auto-adaptive-threshold-sweep-<timestamp>.txt`
- 环境变量：
  - `TRNM_AUTO_HOT_STREAK_RATIO`（默认 0.22）
  - `TRNM_AUTO_REORDER_MIN_MARGIN`（默认 0.04）
  - `TRNM_AUTO_REORDER_MIN_HOT_KEY_SHARE`（默认 0.06）
- 目标：为 auto-adaptive 触发阈值做小网格校准，并通过“重排预算守门”减少误触发导致的额外重排开销。

### Hotspot 序列实验（non-gate）
```bash
TXS=10000 KEYS=256 READ_FANOUT=4 WRITE_EVERY=1 ./scripts/run_executor_hotspot_experiment.sh
```
- 输出：`run/bench/executor-hotspot-exp-<timestamp>.txt`
- 作用：在高热点 streak 场景验证 `auto-adaptive` 是否自动切换到 hot-bucket 路径。
