# Same-worker Work, Host and Paid owner

This component carries the complete W1 relation through its original progress
boundaries while a real native worker checks the original acquired Host
authority. It is an implementation boundary for the next Node and batch
integration. Its output establishes a Work relation; it cannot commit a block,
grant shared public Paid admission, or grant a new parent authority.

## Runtime

The ten checked HIA sources contain the owner, resumable W1 arithmetic,
embedded Host/resource and same-thread Paid methods, the literal Linux adapter
emitter and the private fixture entries. The pinned native compiler compiles these sources.
No Python interpreter, assembler, Rust function, dynamic loader, external clock
value, caller TID, caller generation or caller-supplied success bit participates
in the emitted static executable.

The production entry acquires the fixed parent once. Its boot identity, parent
device/inode/owner and five limits remain immutable across the actual child
birth. The child obtains its own actual TID and performs fresh membership,
boot, limit and final-inode checks against that snapshot. A successful complete
proof has 1,099 ordered W1 progress points and 1,101 worker Host checks. A parent
replacement or changed boot does not authorize a new context.

The original complete Host check runs before replay, within every progress
callback, and at the ordinary terminal boundary. Cancellation precedes the
deadline check. The callback checks cancellation/deadline, then Host, then
cancellation/deadline again. An ordinary terminal Host error precedes the Work
result. Only a successful result reaches the final task deadline. A CLOCK1
failure follows the explicit native panic boundary, publishes no product, joins
the owned child, and skips ordinary after-sampling. This is different from a
regular rejected relation or cancellation.

Aggregate resource sampling retains an actually verified parent FD across
CPU, memory and PID reads. All three reads complete before parsing. The FD
closes before the second fresh Host check. CPU deltas preserve checked
subtraction order; memory and PID values remain point observations. Main output
and after-sampling occur only after actual clear-TID join. A shared FUTEX_WAIT
observes that join; private futexes only coordinate child readiness/start.

The private SHA implementation reduces arithmetic overhead while retaining
the original request, task/ticket/transcript definitions, product and all
progress points. The frozen Work/Host/resource sources remain complete build
inputs and are not changed by this component. The private SHA entry exercises
the exact optimized implementation against independently computed SHA-256.

## Interfaces and qualification

The build module takes --output DIR and builds all ten native sections and
the production, fixture and closed-FD images. Its source manifest owns 38 Work
files, including all ten HIA sections and the complete private Paid Rust hook. The qualify module takes --output
DIR --require-trace and performs the complete finite native corpus, primitive
controls, actual syscall traces, trace-admission controls, 18 owned Work CLOCK1
fault processes and 16 separate Paid clock processes (one positive and 15 faults). The flag makes missing or denied tracing a failure. It never
changes ptrace policy.

The rust_oracle module takes --repository REPO --bundle DIR --output DIR
--target-dir DIR. It first admits the complete current source and artifact
closure. It copies the complete original source graph, appends only private
cfg(test) children, builds the original Node library with the explicitly bound
Rust 1.95.0 toolchain and rust-src, runs 44 retained original Host tests and
executes 57 original-method histories against the actual native observations.
The original finite Paid begin/checkpoint/finish methods are reached through a
private child of the complete scalar_cpu module. The reader compares actual
checkpoint counts, known/Unknown settlement fields, worker counts, failure
latches and each run's own CPU conservation. Independent original and native
CPU nanoseconds are never required to be equal.
All original production prefixes, private hooks, tools, std sources, corpus
and independent executable are checked again on every completed path,
including failures. The four native protocol controls without an original API
equivalent remain explicit.

The physical fixtures create files only beneath the private output directory.
They exercise exact original parsing and fresh-check transitions; they do not
represent production authority for the system cgroup parent. The closed-FD
diagnostic image actually closes its captured parent before fstat and observes
EBADF. The native production image cannot enable this fixture.

Both startup handshakes capture their private state in one 32-bit load before
testing one, zero or an invalid value. If publication occurs after a captured
zero, the real futex wait returns EAGAIN and the loop observes the published
one. This retains the current single-load race fix in the Work/Paid layout.
The separate `hia.tools.qualify_work_handshake` regression selects
`--layout work-paid-v2` for these images. It requires actual compiler and emitter
receipts for the unfixed and fixed builds, identical image lengths and no byte
changes outside the two 20-byte loops. Its 24 hardware-breakpoint controls
exercise both profiles and handshakes, actual zero-to-one publication, invalid
two and invalid `0xffffffff`, real clear-tid joins and fatal exit 88. The earlier
`work-owner-v1` layout remains explicit for its bound historical source and
images; its 40-byte closed-FD shift is distinct from this layout's 50-byte shift.
The regression never patches instructions or substitutes syscall results.

Reports bind every required source, the exact compiler, emitted images,
complete native input/output frames, actual raw traces and original execution
receipts. Reports are qualification evidence and do not become runtime
authority. Trace exit notifications are optional under strace -qq. Every
notification that does appear must identify one of the actual threads exactly
once after its terminal syscall. An absent notification is not fabricated.
Signal returns are consumed only inside the actual worker's private gate. The
trace audit covers both an interrupted ACK read and delivery immediately after
that read succeeds, without replaying a successful read. Fourteen separate
signal controls retain three accepted observations and eleven corrupt cases.

The primitive observer captures each complete backing buffer immediately before
and after every actual native flat call, including both 32-byte guards. Original
bytes are retained as 4 KiB content-addressed chunks, whole-buffer snapshots and
an ordered call stream. The separate reader reconstructs every byte and checks
the complete 175-control roster, initial inputs, immutable inputs, continuation
chains, progress, products, extent refusals and owner-identity refusals. It also
checks exact file rosters, strict JSON types and directory-descriptor fences.
The recorded native CPU intervals surround only the actual function calls;
chunk hashing and evidence I/O are separate observation overhead. Earlier
records that did not retain these buffers remain explicitly non-replayable.

## Integration limits

The HIAPW001 output has a 2,304-byte fixed prefix: a 512-byte header,
three 256-byte Host receipts and one 1,024-byte PWPAY001 Paid receipt. Ordered
40-byte progress records and the optional complete product follow. The public
production reader rejects the preceding HIAWO001 layout and requires a retired,
known same-thread Paid receipt for a successful finite relation.

The standalone entry owns one finite four-second interval. A Node caller must
retain its earlier private request deadline and original acquired snapshot;
starting this entry cannot renew an intake budget. Paid.history_checkpoint,
the full shared paid account, request intake, batch dispatch, persistence and
Node lifetime have not been closed by this component. Original Rust controlled
CLOCK1 fault equivalence remains separate from the native 18-process fault
qualification. No local fixture grants production fixed-parent qualification.

The original 0.25 CPU / 2 GiB / zero swap / 256 PID profile, four-second service
window with 16 attackers and 1,800-second history limit are unchanged. Finite
native relation or original-method PASS does not imply those full service gates
passed. Failed and unknown development observations are retained separately;
they are never relabelled as a new source candidate's successful result.

## Owned Work clock evidence

The primitive evidence retains complete guarded before/after bytes for every actual invocation.
The original CLOCK observer adds a parent-owned observation that survives its actual scoped child
panic and consumed join. It calls the unchanged original task_alive, W1 progress verifier and
final resource helper. In the controlled no-vDSO fixture, exactly one selected worker
CLOCK_MONOTONIC call fails; the four-second original deadline remains unchanged.

The independent raw reader binds every event to the actual clone lifetime, actual per-thread
clock ordinal, actual child exit and consumed original glibc join. The kernel's zero at a
captured futex return remains distinct from glibc's subsequent joined-TID value of -1.
A child that already exited need not cause a futex wait; an unobserved zero is never invented.
The CLOCK input uses the same explicit original_cases projection as the ordinary original
observer, preserving the request bytes and all default control values. The request deadline
uses the first actual CLOCK1 sample after the owner role marker. The unchanged
original budget constructor first creates ListenerIntake, then records its own
watermark: all three main CLOCK1 calls are required in that exact order. Only
the first starts the four-second Work interval; neither constructor can renew it. Captured test-harness clocks before
that role are retained as observations and never define or renew the four-second interval.
It rereads counter file bytes and
the live parent descriptor spanning all three reads. A Work panic must retain the progress prefix, execute the original Paid Drop,
join, perform no after-sampling and publish no product. The raw clock reader
requires the interleaved CLOCK3/CLOCK1 Paid calls and their actual charges,
including cleanup calls after the failing Work CLOCK1. A full positive has
2,200 Work CLOCK1 calls and 1,103 each of Paid CLOCK3 and CLOCK1 calls; the
original private raw observer captures all 4,406 worker calls. Normal-vDSO and private raw-fallback
positives are distinct controls; fault behavior is not inferred for ordinary vDSO execution.

These additional controls require a fresh full-source qualification and original comparison.
They do not qualify fixed-parent production authority, the complete Node, shared public Paid checkpoints,
or the unchanged four-second / sixteen-request production service gate.

The Paid controls use the unchanged zero-target request to isolate the actual
begin, checkpoint, finish and Drop methods. They retain their own source-bound
roster; the 18 dense Work faults retain a separate roster and original source.

| `constructor-clock1-eio` | Second main CLOCK1 fails before worker birth: the native budget constructor, or the original ListenerIntake constructor. |
| `begin-clock3-einval` | Owner CPU sampling refuses begin. |
| `begin-clock3-eio-fallback` | The original one-time CPU fallback succeeds. |
| `begin-clock3-persistent-eio` | Both original CPU attempts fail. |
| `begin-clock3-invalid` | The actual returned CPU timespec is invalid. |
| `reserve-clock1-eio` | Reservation clock fails while the global mutex is held. |

The original qualifier executes two independent positive processes (normal
vDSO and private raw clocks) and these 15 faults. The native qualifier executes
its own positive and the same 15 named fault profiles. The raw reader requires
two native main clocks and three original private main clocks, except for the
constructor failure, which terminates at its second call. The original budget
watermark is its third call; the native budget watermark is its second. These
timestamps are never equated across independent executions.

Paid uses the existing owned-child tracer. Its explicit complete-capture mode
records all write bytes, actual clone arguments,
birth and retirement events, role markers, futex observations and each returned
timespec. A reader reconstructs the complete stdout/stderr and injected-call
roster from those events. It checks exact CPU intervals, refill rounding and
ceiling, the one reservation, live debits, residual settlement, poison state
and known/Unknown receipts. It cannot obtain a new authority from a report bit.

Each complete Paid qualification also requires 27 actual raw-reader controls:
two accepted copies and 25 rejected mutations. All 15 fault injections are
individually removed in retained complete copies; ten further controls cover
schema, extra authority, exact JSON types, clock/event disconnection, a coherent
CPU change, thread retirement, executable identity, output truncation and a
missing constructor clock. Native and original controls have distinct rosters.
The separate Work CLOCK observer retains its own complete syscall, descriptor,
thread and clock ledger. Bulk reads of the stopped child's actual memory and
counters of completed clocks reduce observation overhead. Protected memory,
short reads and missing bounded string terminators fail capture. Entry/exit
events, actual timespec bytes and the original four-second deadline remain
mandatory. The existing Work raw reader independently requires 32 controls: two accepted
copies and 30 rejected mutations.

The observer has a separate mandatory qualification gate. It forks one owned
Python child, installs two readable pages, one protected page and a final
readable page, then keeps that child stopped throughout 23 actual memory
controls. Eleven complete byte ranges and four bounded strings compare the old
PEEK reads with the bulk reads. Seven controls require exact short-read,

control performs no memory read. Complete permission maps, child ownership and
stop state, all read bytes, the actual kernel's 8-of-16 short transfer, child

Twelve additional raw-reader controls retain two complete accepted copies and
ten precise mutations of those actual memory files. The independent reader
reconstructs each prescribed mutation, rechecks complete identities and
reproduces the exact acceptance or refusal reason. It rejects another source,
schema, authority, child type, readonly memory, permissions, short-transfer

The same gate replays every event in all 20 actual original Work clock streams.
It compares the old completed-clock scan with incremental per-TID counts,
preserves the independent role reset and all 18 actual injection positions, and
binds complete returned timespec bytes. Normal-vDSO captures may have no

raw controls: its one Python child is recorded separately from all Rust and

Public Work source admission runs 77 tests; production frame admission keeps

## Exact evidence types

The public bundle reader compares complete decoded native frames with their raw
bytes using exact recursive JSON types. Integer counters, domains, progress
ordinals and byte lengths cannot be replaced with equal-valued booleans or
floating-point numbers. The same comparison binds source maps, build receipts,
trace observations and required control counts. Duplicate fields and non-finite
JSON numbers are refused. These checks apply to the canonical reader used before
original execution, in addition to the CI archive reader.

A prior candidate accepted coherent metadata edits from integer zero to false
and from integer one to 1.0 while the actual native output remained unchanged.
That reader failure and the prior real executions remain separate evidence; a
new reader source identity does not relabel those executions as a new complete
source qualification.
