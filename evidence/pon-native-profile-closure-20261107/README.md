## Actual native queries, cancellations and interruption

The new local fixture command, `execute_observed_v1`, exports at most 65 actual
callbacks: one seed hash and 64 step-oracle queries for a complete replay. It
captures the exact 139-byte seed preimage and 145-byte step preimages, original
authority identity, policy, epoch, generation, operation sequence, request,
receiver, candidate and ordinal. The original receipt increments cost before
an observer can cancel the invocation.

The raw NDJSON prefix is created exclusively and file-synced after every event.
A controlled process exit after the seed and step 17 leaves 18 actual records
and the original STARTED journal. The test snapshots those original bytes before
the normal reopen converts the existing operation to UNKNOWN. That reopen emits
no new query, permits no rerun or refund, and retains the original 64-step upper
bound. The observed 17 steps are inside that upper bound, not an extra charge.

The three explicit cancellation points are seed, step 17 and step 64. All just
completed queries remain in the receipt; cancellation after the last query does
not become a successful endpoint receipt. Cached reopens produce no new query.
A forged endpoint still performs and exposes the actual 64-step replay, while
proof framing rejection produces no fictional query. Existing export paths
cannot be overwritten to hide an earlier attempt.

The test logs contain the original configuration, preparation, requests,
responses, query prefixes, process outputs and reader inputs. Retained failure
directories additionally contain the actual SQLite journal and other original
fixture files, including the before-reopen copies. Their file hashes are
checked against the retained manifests. These are controlled fixtures; their
keys, targets, customers and funding are not independent external parties.
File synchronization and create-only copies are not a proof of power-loss
durability, immutability, clone resistance or rollback protection.

The native implementation legally caches its fixed SHA-256 prefix. A logical
step query is not a claim that the entire prefix was recomputed or that a
particular physical cost was unavoidable. Observer metadata hashing, encoding,
logging and synchronization are extra work inside measured owner wall time;
they are not extra security-seal step queries. Test-controller snapshots and
reader rehashing are outside the original invocation's query count.

## Current native payment and task membership

`observe_current_native_task_operation_v3` reads the original Node and M12
owners. It checks the complete expected operation binding and funded TSC1
contract, the latest already recorded reconciliation epoch, and the complete
current journal checkpoint. A retained historical prefix is insufficient.
The original delivery and monetary transition must both be present on the
selected active block and generation, with exact original operation identities,
gross escrow debit and beneficiary credit. Current pins and checkpoints are
checked again before returning the read-only report.

The read does not create reservations, execute a task, move a journal floor,
make payments or advance the reconciliation epoch. `consumer_epoch` names an
existing reconciliation coordinate; it is not an authenticated consumer state.
`target_scope` and `target_receipt` are commitments, not established external
target permission. TSC1 instance IDs, task-content commitments,
`qualified_work` references and grouped policy digests keep their original
domains. In particular, making a policy that contains the TSC1 Task ID into
that same contract's `qualified_work` would create a circular commitment.

## Five qualification conditions

| Condition | Established by this implementation | Still requires authentic external evidence |
| --- | --- | --- |
| Public network query attribution | Actual bounded native query originals and a reader for the union of declared owner sources | Every actual owner, offline/preparation/delegate/helper path, complete query coverage and actual control relationships |
| Independent tasks and target authorization | Original prospective operation fence, complete native contract comparison and bounded current task/payment readback | Independent issuers, unbiased assignment, trusted prequery authorization, current target and consumer authority at actual use |
| Genuine demand | Original native delivery and payment replay, with current membership separated from retained history | Independent customers, external budgets and funding origin, actual current consumer use and external settlement proof |
| Full cost transfer | Typed cost forest and payer/beneficiary consistency, original gross debit separated from credit | Authentic complete meters, preparation and failure costs, machines and networks, and who actually bears or receives each cost |
| Adoptable weight rule | Explicit classical-query denomination and the lawful cached-business zero lower bound | A valid relation to the cheapest legal physical implementation and formal native consensus profile registration |

The lowest cost among finitely measured legal strategies is an observed upper
bound on the cheapest legal implementation, not a proven positive lower bound
over all legal strategies. None of the five external conditions is enabled by
accepting a Boolean supplied with a fixture or by a successful code review.
