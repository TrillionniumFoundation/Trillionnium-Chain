# Trillionnium-Chain 整链 PQ-128 证据门禁（离线预审工具）

> **默认结果：NO-GO。** 这是本地证据一致性预检器，不是密码学安全证明、NIST/FIPS 认证、链上激活证书，也不是对最新 `main` 的审计结果。**未经独立审查不得使用“整链已达 PQ-128”措辞。**

## 本次实际交付

- `pq_preflight.py`：**标准库** Python 3 工具，六类 fail-closed 门禁；不依赖 GitHub、Rust 工具链或外部服务。
- `examples/template.json`：强制显示未知状态的 15 类授权入口、证明、矿工、迁移、性能、恢复检查模板。**模板不预填通过项。**
- `examples/template-result.txt`：在空证据下生成的真实 NO-GO 输出。
- `tests/test_pq_preflight.py`：21 项本地回归测试。正向测试只使用**合成的自报回执**，从不证明实际抗量子安全。
- `SECURITY_GATE_SPEC.md`：六门禁的真实验收条件与安全原则。
- `SOURCE_MAPPING.md`：历史源码入口/Issue/PR 映射与恢复 GitHub 访问后的实施顺序。

## 运行

```bash
# Python 3.10+，无需第三方包
python3 -m unittest discover -s tests -v
python3 pq_preflight.py examples/template.json --json

# 从全空门禁生成新模板
python3 pq_preflight.py --write-template evidence.json

# 在人工/独立验证、下载证据文件、计算 SHA256 后：
python3 pq_preflight.py evidence.json --evidence-dir ./evidence-files --json
```

`0` 表示**声明和本地回执的预检一致**，不是安全认证；`1` 表示有未通过门禁；`2` 表示无法读取/解析。即使得到预检全清，也必须另行取得独立密码学评估、现场测试与网络激活证明。

## 证据文件约定

每一项证据引用 `evidence[]` 中的 `id`。例如：

```json
{
  "id": "tx-hybrid-authorization-negative-v1",
  "path": "tests/transaction-authz-negative-test.log",
  "sha256": "<64 位小写 SHA256 十六进制>",
  "commit_sha": "<此次评估的 40 位源码提交 SHA>",
  "status": "passed",
  "independent": false,
  "reviewer_id": null,
  "claims": ["account_transactions authorization"]
}
```

要求证据文件**真实存在于 `--evidence-dir` 下**且哈希一致，`commit_sha` 必须与 `baseline.main_sha` 完全相同。`claims` 必须精确包含被验证项名字，以防任意日志冒用验证结论。指定独立评估的证明还须填 `independent=true` 和 `reviewer_id`，但本工具不能对姓名或第三方机构做密码学鉴别；必须保留独立签署的审计文件并线下核对。

W1 门禁额外引用 `w1_proof.backend_manifest_evidence`，该证据文件需是对应提交中的真实后端 JSON 清单。工具递归查询 `pq_128_security_qualified` 和 `production_consensus_activation`，每个键须**恰好出现一次且为 `true`**。这可防止只在顶层证据 JSON 中虚构通过而后端实际仍为 `false`。即使两个标志皆 `true`，它们也不能代替安全论证。
