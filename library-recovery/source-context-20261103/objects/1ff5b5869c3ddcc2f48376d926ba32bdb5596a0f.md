# PQN2: native C/OpenSSL PQG1 dual-possession conformance (HOLD / NO GO)

Exact stacked parent: Chain PR #431, `c62339bc255b8ba59f1081552c1351109cded287`.
This adds a second independent native C11 verifier for one source-pinned PQG1 migration statement. It is an OFFLINE read-only research check, not a production Rust M01 signer, M13 import, authority issuer, PQL1 state transition, PoN work certificate, or deployment. Existing W1/PNW1, Ed25519 transactions, Chainwork, QTX1, branch rules, network protocol, and production flags are unchanged.

## Threat boundary and exact inputs

`pqg_native_verify.c` consumes four **separate local regular files** with O_NOFOLLOW leaf protection and strict ceilings:

1. `snapshot.bin`: untrusted canonical PQG1 bytes, 1-128 accounts and at most 256 liabilities; maximum 65536 bytes. Includes old/new network, source head, withdrawal head, new profile, total issuance, sorted old accounts and sorted obligations.
2. `anchor.bin`: **292-byte PQA1 caller-pinned expected values**, with `PQA1` magic, SHA384 PQG1 source digest (48), legacy network(32), new network(32), old head(32), independent withdrawal head(32), new profile(32), issued units(8), expected old Ed25519 signer(32), expected ML-DSA-65 key ID(32), observation time(8).
3. `claim.bin`: **3449-byte PQM1** with magic(4), old Ed signer(32), new ML-DSA key ID(32), expiry(8), Ed25519 signature(64), pure ML-DSA-65 signature(3309).
4. `public.pem`: ML-DSA-65 public SPKI only, maximum 8192 bytes. Strict DER OID `2.16.840.1.101.3.4.3.18`, 1952 public-key bytes, algorithm parameters absent. Reject trailing non-whitespace PEM data and non-ML-DSA keys.

Only the independently admitted source owner may supply trusted expected anchor bytes. The tool cannot make such trust from a self-consistent attacker-created snapshot/anchor pair.

The C verifier reproduces the upstream `pq_genesis_handoff.migration_statement` verbatim:
`TRNM/PQ/GenesisMigration/v1\0 || SHA384(SOURCE_DOMAIN || BE64(len(source)) || source) || old_network || new_network || old_head || withdrawal_head || new_profile || LegacyAccount56 || pq_key_id32 || BE64(old_generation+1) || BE64(expiry)`.

The account and liability checks preserve old `next_nonce` and generation bytes; verify ordered unique accounts/obligations, owner existence, all positive liabilities, exact u64 issuance conservation, distinct network identifiers, expiry and no u64 generation wrap. Both strict RFC8032 Ed25519 (canonical curve points and R, S below group order, small-order rejection, actual OpenSSL signature verification) and ML-DSA-65 (OpenSSL EVP) must verify the **same canonical statement**. No signature-valid boolean, key downgrade, hash-only fallback, JSON or arbitrary command execution is accepted.

Success prints **only** `PQN2_VALID_RESEARCH_OBSERVATION_ONLY`. It does not expose balances, create accounts, authorize import, update a database, or issue a final-use capability.

## Executed tests and evidence

Run in `formal/pon-nakamoto-v1`:

```sh
PYTHONWARNINGS=error::ResourceWarning python3 -m unittest -v test_pqg_native_verify.py
PQN2_SANITIZE=1 ASAN_OPTIONS=detect_leaks=1:abort_on_error=1 PYTHONWARNINGS=error::ResourceWarning python3 -m unittest -v test_pqg_native_verify.py
```

17 normal and 17 ASan+UBSan negative/positive tests pass on the named local host; 0 failures. Uses real generated Ed25519 and ML-DSA-65 signatures, two old accounts and two escrow/task liabilities; includes all input identity/expiry/signature mutations, malformed/noncanonical Ed compressed R and S, weak old identity, forged alternate anchor, changed liability, wrong PQ key, malformed PEM, symlink and truncated-frame refusal. See `evidence/pon-pq-genesis-native-v1` for raw output and hashes.

## Mandatory blockers still open

- Full product **Rust** M01 provider, HSM/key custody, parser integration and independent cryptographic review; C11 demo is not the deployed Rust node.
- Authentic independently accepted legacy source tip/snapshot/withdrawal/effects, rollback floor, freeze cutoff and consensus governance. An adversary able to forge a classical signature after quantum compromise cannot be fixed by dual possession alone.
- One claim is only one owner: a complete import must check all accounts, quarantine, rewards, tasks, quotas, escrow, uniqueness across target keys and durable exactly-once whole-import publication.
- PQL1 currently creates `next_nonce=1` and does not import PQG1's quarantined identities or liabilities, and computes a different genesis root. **Do not translate PQG1 records directly into its constructor**; that would lose source nonce floors, locked balances and namespace identity. A new versioned native state schema/importer plus controlled reorg, revocation and anti-rollback is required.
- Signed, authenticated P2P node, hostile multi-operator WAN/fault tests, quantum effective-work proof for PoN, full Hepta authority and future model efficacy, independent external acceptance. All Chain production flags remain false.
