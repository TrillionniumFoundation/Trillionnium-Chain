# Private windowed single-row verification

This synthetic memory-only qualification accepts the original cursor request
(position, request length, and TCM1 manifest). The start operation binds
the selected original row and copies its expected length and SHA-256
into privately owned scratch. No subsequent operation supplies those
fields, a digest, a row offset, a filesystem handle or a security claim.

The test child retains one disjoint scratch span of 69,632 initialized
bytes through the entire finite flow. The caller is the private fixture,
not a general API. It supplies an eight-byte little-endian operation tag:
start (0) followed by little-endian u64 position/want, u32 manifest
length and exact manifest; feed (1) followed by 1–65,536 immutable bytes;
finish (2) alone. Up to 4,194,304 bytes may be fed. The caller must stop
on any refusal and invoke finish only after all private row bytes are
supplied. A logical zero request or EOF needs no feed. This memory entry
does not observe physical descriptor EOF.

The stock HIA kernel chains SHA-256 across windows and stages only the
selected byte interval in its own scratch, at most 65,536 output bytes.
It never treats an independently supplied digest as a match. The finish
path compares the carried digest before the original row length, then
checks destination capacity and publishes the original next-position and
count (two little-endian u64 words) and selected bytes. Wrong digest or
absent row is 247; wrong width after matching digest is 248. An otherwise
valid logical result beyond the private result cap refuses, rather than
clipping. There is no unbounded owner or trust relaxation. Successful
start/feed, refusals and repeated finish never change the output.

The unchanged Rust held-reader comparison consumes the same synthetic
manifest and complete generated bytes, and both stock backends execute
the continuation. Scratch remains in a one-child owner; the qualifier
only transports fixture bytes and validates boundaries. The existing
64 KiB physical sealed FD0 fixture, earlier memory reader, and all their
caps are unchanged. This result does not qualify a streaming file adapter,
actual payload/cache, OS permissions, production ownership or retirement.
