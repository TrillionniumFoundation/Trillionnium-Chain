# Selected PFT inspection: first engineering observation

The new adapter borrows the original adoption owner's actual selected TCV1
manifest inside its existing transaction. It accepts no caller manifest or model
expectations as selection authority. The fresh profile gives explicit meanings
to base/layout/tokenizer; it changes no existing profile or selection policy.
The result is nonauthorizing metadata, with no model handle or prediction.

The single new offline gate ran on 2026-11-28 from 03:21:20 to 03:21:28 UTC:
6 new binding/refusal groups passed; the previous 9 loader and 11 arithmetic
groups were filtered out. Cargo compilation plus controls took 7.928254977 s;
the test runner reported 0.03 s. These are engineering observations, not a
training speed or inference benchmark. The fixed 120 s deadline did not expire.
The prior loader gate remains separately recorded at 7.654649710 s, without replay.

Rust 1.95.0 compiled the pure binding harness against 21 dependency records
matching the original Chain Cargo lock versions and archive checksums. The
resolved serde_json features included arbitrary_precision; the actual Cargo
fingerprint recorded `-D warnings`. Source hashes matched before and after.
Only task-owned Cargo home, target and vendor directories were used.

The six groups cover the independent frozen profile digests and owned result;
old family/profile/tokenizer and changed file graph refusal; independent
payload/contract/base pins; missing selection and payload bounds; raw bytes
before interpretation; and malformed selected bytes still needing the complete
internal candidate/contract/head/shape/numeric/LE validation.

The harness does **not** compile or execute the real selected-owner wrapper,
the original SQLite owner, or the full Chain crate. Those exact-source checks,
including the two actual SQLite controls added in the parent PR, remain pending
repository CI. No owner stub is used. The original CI first failures remain.

`ORIGINAL_ARTIFACTS.json` retains exact SHA-256-bound base64 bytes for the original
receipt, stdout/stderr, compiler version, effective Cargo fingerprint, and minimal
harness Cargo manifest/lock/config/source. `FIRST_GATE.json` is the same original
receipt; `native_first_gate.py` is the exact single-run driver.

No private matrices, features, trajectory, label, DEV/final input, historical
inference or training are read here. Source authentication, current permission,
native adoption, FinalUse, model quality, real user B, reward, payment and
production activation remain unestablished. An inspection may become stale
as soon as the original transaction ends and cannot grant later execution.
