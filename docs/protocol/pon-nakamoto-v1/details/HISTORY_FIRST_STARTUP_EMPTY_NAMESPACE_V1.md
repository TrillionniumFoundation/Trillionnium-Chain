# Bounded first-Startup empty-namespace closure

This is a fresh, explicitly authorized research capability. It closes one known
failed **first** Startup after a source-pinned guardian actually kills and reaps
its process, while the complete reserved Native container remains exactly as it
was before the original Startup signature. It never removes, resets or overwrites
Native, and never fabricates NotStarted or a zero CPU receipt.

The domain is `TRNM-HISTORY-STARTUP-NO-NATIVE-CLOSURE-V1`. Its journal record schema
is `restricted-history-startup-no-native-closure-record-v1`. Existing V6 work
signatures and settled-epoch recovery signatures retain their original meaning.
All original runtime limits and all 21 retained native methods remain mandatory.
The new method and original ignored child helper form an exact 22/0/1 gate.
Implementation and source checks do not establish execution: Node compilation,
strict Clippy and the entire exact-source native group require new hosted results.

## Entry conditions and evidence

The protected closure input pins both role keys through the original identity,
the exact current outside journal anchor and journal path, the reserved parent
path, and independent source, actual executable, fixture, guardian, process
observer, shared process guard and preparation-document hashes. The separately
signed closure authorization binds the exact original signed Startup bytes,
its operation ID and intent hash, the exact original dead-process receipt bytes,
the current budget ID, a fresh nonce and closure ID, a finite CPU allowance and
its own issue/expiry interval.

The fixture embeds the actual compile source supplied by the exact-source gate;
the executing child compares that value with its run environment. The guardian
checks the actual executable hash, both imported observer files, its own bytes,
the actual child's compiled source and the fixture-byte hash. This is a bounded
thread-only fixture attestation. It does not prove historical closure of arbitrary
process trees, escaped sessions or privileged external writers.

The journal must replay to all of these conditions:

- There is no pending scope, exactly one consumed epoch, exactly one used operation
  and exactly one known settlement. There are no effect markers or prior recovery
  or closure records.
- The single operation is Startup. Its actual settlement has no native ID, a
  nonempty failure, a known positive owner CPU receipt and zero spawned, started,
  finished and known workers. The CPU receipt arithmetic remains the original
  V6 arithmetic, and `live_refused` is false.
- The spent ledger equals that original Startup allowance. Its exact signed
  envelope, operation, intent timestamp and current outside anchor match the
  independent dead-process witness. The open epoch is that Startup's epoch.

The error string alone grants nothing. Neither a missing `native.sqlite` nor a
directory that is empty only at recovery time grants anything.

## Birth-to-death namespace reservation

Before the fixture signs Startup, the guardian performs a create-only `mkdir`
for a dedicated private parent, a create-only private lease file and a private
empty `native` child directory. Existing paths are refused without deletion,
adoption, truncation or permission changes. The parent contains exactly those
two entries. The guardian fsyncs the lease, child, parent and enclosing directory.

The lease includes the exact parent and journal paths, original identity digest,
preparation-document hash and a random reservation ID. The guardian holds the
parent and child directory descriptors and an exclusive lease flock continuously
through preparation, signing, process birth, stopping, SIGKILL and actual wait4.
An incomplete preparation error preserves all created bytes and cannot produce
a successful closure witness.

The before/after snapshots include complete directory inventories and each held
object's device, inode, type, exact 0700/0600 mode, owner/group, link count, size,
mtime and ctime. The child remains empty; the parent has exactly two entries;
the lease is a single-link regular file with exact retained bytes. The after
snapshot must equal the before snapshot. The observer retains the existing limit
of four complete process-parent snapshots and requires two matching complete
observations. A missing or inaccessible process row remains unknown.

At closure and pinned publication repair, the Rust entry point independently
opens and holds the reserved parent, child and lease. It verifies held-versus-
visible identities, exact inventories, lease hash and parsed identity/journal/
preparation bindings, and obtains the exclusive lease. Child paths are opened
relative to the held parent descriptor. The journal owner lock and these held
objects survive the append or complete publication repair. Any extra entry,
replacement inode, changed metadata, lease contention or changed bytes refuses.
There is no namespace write in this capability.

## Accounting, time and replay

The original 4-second predebit and actual CPU receipt remain unchanged. A new
finite closure allowance is charged in addition to the original reservation;
it covers the **entire** actually reaped process CPU upper bound, including CPU
outside the original measured Startup interval. The wait4 counter is interpreted
as two microsecond-quantized counters, retaining the original decimal spellings
and adding one unit per counter. That upper bound must also cover the original
known CPU receipt. It is a conservative extra charge, not an exact residual
measurement and not a refund.

The fresh closure nonce and ID are consumed. Original nonce limits and lifetime
ceilings still apply. The closure creates neither a CPU epoch nor a work permit.
After an old run budget expires, a fresh valid closure authorization may close
this exact dead epoch, but cannot authorize Startup or other old V6 work. A later
ordinary signed Budget and ordinary new Startup are required; the new Startup
begins with zero stored credit. The native fixture keeps the original lifetime
ceiling during renewal.

Insufficient remaining lifetime allowance is a refusal. This capability does not
silently raise a budget ceiling or accept an unknown pending Startup, a later
failed Startup, a completed Native initialization or a changed container.

## Interrupted publication

The new event uses the original create-only pending-file, fsync, hard-link,
directory-fsync and pending-unlink journal publication primitive. A complete
unpublished record can only be repaired through the dedicated pinned wrapper.
Generic journal publication explicitly rejects this event because its own
authority does not contain the required namespace/source/binary pins.

The pinned wrapper requires byte-for-byte equality of both original signed
closure and dead-process receipt, the exact original frame schema/hash and
journal path/identity, the independent pins and the exact empty container. It
validates the original closure at **the original frame timestamp**, and the fresh
publication authorization at the current time. An old authorization's expiration
therefore does not strand a complete original frame; it also does not revive old
running authority. Prefix replay rechecks the original nonce and ledger. Retried
publication cannot charge twice.

The new mandatory native method performs a real SIGKILL after this new event's
pending file is fsynced, actually waits for its closure signature to expire, then
requires fresh pinned publication repair and an identical idempotent retry. It
also rejects expired current repair authority, different original signed bytes,
different original receipt bytes and an incorrect independent executable pin.
Other publication cuts use the unchanged shared primitive but are not claimed as
new-domain execution until their own observed tests exist.

## Mandatory native method

The first actual child uses a validly signed but wrong initial generation. The
normal paid Startup parses real fixture materials, reaches BeforeNode, refuses
the initial frontier before any Node state read, and persists its actual known
positive CPU settlement. It retains the journal lock until the external guardian
actually stops and reaps it. The guardian independently reads the complete
original journal transcript and the unchanged reserved container.

The outside fixture exercises fresh-domain, authority, original-intent, outside
anchor, nonce, used-ID, independent pin, timing, whole-process CPU, lifetime,
lease-content and lease-contention refusal paths. It then lets the original run
budget expire, writes the separately signed closure, kills its administrative
publisher at the real file-synced boundary, and repairs the exact complete bytes
after the old closure signature expires.

A new ordinary process then receives a separate ordinary budget and Startup,
starts with zero credit, validates with two actual workers, activates, performs a
paid Close, drops the owner and cold-reads the journal and SQLite markers. The
expected final ledger is six consumed IDs, five actual known settlements and
six times the original 4-second allowance: 24 seconds. The closure itself is the
one extra charge without an invented settlement. The first failed Startup's
record bytes must remain unchanged, and its freshly re-signed closure must fail
after the journal advances.

A separate genuinely observed failed first Startup provides the physical
negative: adding any Native bytes after the guardian's actual death observation
must refuse closure, leave the journal unchanged and preserve those bytes. The
test never deletes them to recycle a positive witness.

## Next bounded partial-initialization capability

The existing generic `initializing.json` contains only schema, parameters and
genesis. It does not record the History intent, epoch, exact material bytes,
budget reservation, namespace birth or an actual SQL commit. It cannot be
promoted into such evidence by this capability.

A later independent protocol can make progress without arbitrary Native reset by
persisting the following original-Startup facts under a fresh schema. This is a
design boundary, not an implemented or executed feature of this increment.

| Durable stage | Exact new binding required | Bounded continuation after actual death |
| --- | --- | --- |
| Reserved, before any Node namespace write | Original signed Startup/intent/epoch, journal predecessor and reservation, complete material-role bytes/hashes, settings/genesis, private namespace/lease identities and birth record | If the complete container is unchanged, use an explicitly authorized no-Native closure; never infer birth from a currently missing file. |
| Initialization intent published, no committed genesis | Exact owner marker, original initialization intent bytes and source/binary pins, actual SQLite file/sidecar identities, schema and transaction outcome | Hold original namespace/locks; positively prove no committed genesis/effects and preserve partial bytes. An explicit finite paid continuation must select that exact intent and finish or quarantine only a proven fresh, never activated reservation. No overwrite or database reset is implied. |
| Genesis transaction committed, finalization incomplete | In the same actual SQL transaction, store original History intent/material/settings/owner binding, schema, genesis block/root, generation zero and complete initial state digest | Independently cold-read exact schema, every initial state row, owner metadata, absence of unrelated effects and commit fact; then authorize only finalization of those exact original marker bytes. |
| Initialized but Startup settlement or acknowledgment unknown | Actual committed initialization binding, original journal pending scope, exact outside anchor, real closed process and unchanged original predebit | A separate pending-Startup reconciliation must retain the unknown original CPU split and conservatively charge the actual whole process; it must not fabricate a known original Startup settlement. |

These records must be created by the original paid Startup before and within the
relevant Native changes. Old partial directories need explicit external authority
that pins their exact current bytes and original available records; absent birth
or activation evidence is a real missing input. Quarantine would preserve bytes
and require proof of a fresh reservation that was never externally activated;
the present implementation grants no such authority. Pending Close, torn frames,
SQLite crash windows, multi-step signed reorg and generic continuous History
admission remain separate open paths.
