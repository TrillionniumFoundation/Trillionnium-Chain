## Legal-work economics and invalid-input service are different

The prior native census retains 115,712 completed attempts, 30,867 verified
hits, 84,845 losing attempts, and all 1,552 unsupported cells in its 3,360-cell
plan. It selects an implementation using calibration samples 0 and 1, then
evaluates that unchanged selection on samples 2 through 7. It does not choose a
new winner after inspecting held-out measurements.

For the historical `pon-matmul-transcript-64-v1` profile, the explicitly limited
cost ratio is
`rho_cost_observed = selected producer CPU / dense lazy-full-limb producer CPU`.
The corresponding observed advantage is its reciprocal. Representative supplied
materials have cost ratios about 0.909 and 0.924, or about 1.100 and 1.083 times
as much work per measured producer CPU as the dense baseline. A rank-one selection
is worse on held-out work: cost ratio about 1.057. These are finite measured
implementations, not a minimum-cost theorem, consensus security bound, independent
hardware result or current Python/Hepta ratio. Honest miners can use the same
legal optimizations. Exact numerators, targets, cohort pointers, setup and cleanup
scope are in [native-cost-readback.json](cell-reference/native-cost-readback.json).

An invalid request may have a cheap construction path and an expensive rejection
path even when the cheapest legal strategy is well understood. Exact-byte cache
hits do not establish resistance to novel forged statements. F0 remains failed
even before this hostile-input qualification; neither gate closes the other.
