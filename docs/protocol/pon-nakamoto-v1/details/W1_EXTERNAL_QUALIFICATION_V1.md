## 2. O04 requires physical observations

The current local capability observation found an `x86_64` host with CPU
affinity 0 through 8. It found no accessible `/dev/dri`, `/dev/nvidia0` or
`/dev/kfd`, no `nvidia-smi` or `rocm-smi`, and no powercap measurement entry.
No independent operator or external hardware execution capability was supplied.
These are observations about the available environment, not proof that such
hardware does not exist elsewhere. The raw observation is retained with this
research increment.

The native campaign can therefore report actual local CPU and wall intervals,
whole-child resource observations, and retained bytes. `energy_joules` remains
null, GPU/ARM executions remain absent, and hardware attestation remains false.
CPU affinity does not establish exclusive use, fixed frequency, an authenticated
device identity, or absence of shared-host contention. No throughput result from
this host is relabeled as a GPU, ARM, energy or WAN measurement.

O04 closes only when the evidence includes actual runs on the declared hardware
classes, the strongest available implementations on each, and independently
controlled operators. Each run must retain exact source/build/plan identities,
all successes and failures, cold/hot/batch denominators, complete proof replay,
real instrument readings with scope/resolution, and transfer measurements where
claimed. Hardware descriptions and signatures alone cannot establish physical
execution or organizational independence. An unavailable instrument remains
unavailable; simulated joules or a CPU emulator cannot fill the field.

complete model release. Neither study is rerun or promoted by this source review.

upgrade. A positive task score does not create chainwork, and a valid W1 block
does not install a model. The pre-disclosure history contract in
[model operations acceptance](MODEL_OPERATIONS_ACCEPTANCE_V1.md) also still
requires the real evaluator owner to durably commit exposure before disclosure;
an offline function call supplies no such owner transaction.

The missing external resources are specific: independently operated hardware
and instruments for O04, and authorized real task/data/model custody plus an
independent evaluator/selector and ordinary next-use service for O06. Their
absence cannot be repaired by adding a passing fixture. The existing closed
