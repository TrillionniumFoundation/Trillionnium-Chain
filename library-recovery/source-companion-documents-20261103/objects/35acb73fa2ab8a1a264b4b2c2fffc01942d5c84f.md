# PQL5N — independent native ML-DSA-65 quorum verifier (HOLD_NO_GO)

This is a **read-only native C11/OpenSSL 3.5+ research oracle** for the PQL5
challenge-fresh witness responses in `pq_pql5_quorum.py`, stacked after Chain
PR #458 (`192480f0c5e1fa6077c8c3bc2b9e1790a02c0552`). It is NOT a
non-rewindable checkpoint authority, trusted source auditor, on-chain PQ account
owner, Node consensus rule, Chainwork evidence, Hepta FinalUse or deployed service.
Do not merge or activate it as whole-chain post-quantum security.

## Fixed inputs and exact native verification

The binary requires exactly three **caller-pinned** ML-DSA-65 SPKI public keys,
2–3 PQL5 signed response files and fixed independent network/import/genesis,
32-byte caller nonce, latest 64-bit sequence and 48-byte frontier ID. The last
six fields are externally supplied trust observations, not produced by this tool.
It accepts only exact canonical OpenSSL `PUBLIC KEY` PEMs with the ML-DSA-65
FIPS 204 OID `2.16.840.1.101.3.4.3.18`, absent SPKI algorithm parameters,
1,952-byte raw public keys, distinct key IDs and regular no-symlink leaf files.

Response structure is precisely 269 unsigned bytes + BE16(3309) + 3309
ML-DSA signature bytes (total 3580). Verify the exact PQL5 prefix and version;
key ID = SHA256(`TRNM/PoN/PQKey/v1\0` || DER SPKI), challenge, caller network,
import root and genesis. A real OpenSSL EVP ML-DSA-65 verifies
`TRNM/PQ/PQL5Witness/v1\0` || unsigned269. Enforce observation time <=
caller now <= expiry and expiry = observation time + 30 without overflow.
A signed empty head is not eligible for quorum. No caller can turn a zero
fingerprint or incorrectly formed decimal value into a valid pin.

Select the highest **observed** signed sequence. A valid result requires at least
two distinct pinned signer keys agreeing on one frontier ID at exactly this
highest sequence; it must match the independently supplied expected sequence/ID.
A lone higher sequence defeats an older majority, as in the original PQL5 rule.
Missing, malformed or conflicting evidence fails closed, never `InvalidBlock`.

`0` only prints `PQL5N_VALID_RESEARCH_OBSERVATION_ONLY`; `2` only returns
`PQL5N_REJECT` on stderr. Nothing mutates a database or transmits a network
request. The native executable accepts no private key or signing operation.

### Command

```sh
cd formal/pon-nakamoto-v1
cc -std=c11 -Wall -Wextra -Werror -O2 pq_pql5_native_verify.c -lcrypto -o /tmp/pql5-native-verify
/tmp/pql5-native-verify NETWORK64 IMPORTROOT96 GENESIS96 CHALLENGE64 NOW_UINT64 \
    EXPECTED_SEQUENCE EXPECTED_FRONTIER96 WITNESS0_PUB.pem WITNESS1_PUB.pem \
    WITNESS2_PUB.pem RESPONSE_0.bin RESPONSE_1.bin [RESPONSE_2.bin]
```

`NETWORK64`, etc., are lowercase hexadecimal bytes, not names. The binary is
only an offline verifier of externally pinned research evidence. Do not expose
this CLI to unauthenticated RPC or wire it into an actual account signer.

## Actual test and adverse outcomes

```sh
cd formal/pon-nakamoto-v1
PYTHONWARNINGS=error::ResourceWarning python3 -m unittest -v test_pq_pql5_native_verify.py
PQL5N_SANITIZE=1 ASAN_OPTIONS=detect_leaks=1:abort_on_error=1 \
 UBSAN_OPTIONS=halt_on_error=1 PYTHONWARNINGS=error::ResourceWarning \
 python3 -m unittest -v test_pq_pql5_native_verify.py
```

Local original-source runs each completed **14 PASS, 1 SKIP, 0 FAIL**. The
skipped integration method checks Python `pq_pql5_quorum.verify_quorum` and
is automatically active when run in the **complete** inherited PR #458 tree;
it could not be executed in the isolated code host where the new two files
were tested. Therefore exact inherited-source native/Python parity remains an
explicit separate verification gate, not silently marked passed.

Tests generate actual fresh ML-DSA-65 private/public fixture keys and sign true
PQL5 responses. They include all **269** unsigned-byte mutations, malformed
signature/frame, Ed25519 downgrade, wrong signer/key, duplicate/outside roster,
wrong network/genesis/import/challenge, overflow/caller decimal limits, fresh
replay and expired responses, higher solitary sequence, fork conflicts,
symlink/noncanonical PEM and large payload denial.

**Retained negative (critical):** a majority of two cloned/reverted witness
stores can generate a *freshly signed* older head. It is rejected against a
non-rewound externally pinned latest sequence and hash; it **is accepted** if
the external caller pin is also maliciously rewound. Native crypto and a 2/3
quorum cannot solve that trust problem. Requires independently administered
non-rewindable anchor, key custody/HSM, rotation, accountability/equivocation
and WAN/physical fault testing with separate operators.
