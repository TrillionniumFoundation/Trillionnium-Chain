## Conditions and negative outcomes retained

The current full native suite reports 1801 passes with no failures; its one
ignored fixture-output helper runs separately. Python checks include real initialization,
entry/revoke scheduling and recovery, as well as separately labelled abstract fixtures.
The full-suite receipt names `/tmp` on ext4 and its actual concurrency; no tmpfs pass
is relabelled as a physical durability qualification. The separate 4,114-block history
campaign uses `tmpfs /dev/shm` and fixed logical timestamps.
It hashes the final database in [its execution receipt](campaign-execution.json).

The live-clock host run uses an explicitly distinct genesis: only chain label and
genesis timestamp differ from the frozen experiment. Source files, overrides and host
readback are bound in [the manifest](multihost/source-manifest.json). SSH authenticates
the owned transport; controller delivery withholding is not a physical network partition.
The [disk-error follow-up](multihost/disk-errors.json) uses new database copies on each
host: foreign trigger, corrupted active value, actual SQLite page-limit FULL, and a
truncated database are refused without accepting partial state. The SQLite limit does
not mean the physical device was filled. The initial harness expected root refusal at
read rather than open and failed early; [that failed run](multihost/disk-errors-initial-harness-failure.json)
is retained along with both driver versions. Product checks and timeouts were unchanged.
All peer processes close at completion. No daemon service, firewall, user key or private
artifact is installed or changed. The source corpus and deliberately public keys are fixtures.

The initial external campaign driver omitted the required `--native` argument for the
parallel command. That invocation failed before executing the benchmark; [its report](campaign-initial-invocation-failure.json)
and raw argument error are retained. The completed long-history result was not rerun or
altered; the corrected exact-source continuation executes parallel and learning separately.
The [parallel samples](parallel/report.json) expose stage counts, conflict retries,
state bytes, RSS and missing VRAM/inclusion/confirmation values. A slower multithreaded
sample remains a slower result. There is no inferred public-chain TPS or automatic speedup.
The [three-cycle model report](learning/report.json) keeps each losing/no-update outcome,
locked reference, source-group partitions and exact parameters. All three attempts leave
the actually admitted public model unchanged and pay zero. They are not three improving
model generations, independent tasks, or the ordinary Hepta product path.

[Structured work costs](work/structured.json) distinguish dense, zero, rank-one and sparse
inputs at the installed ticket target. They time the supplied honest implementation,
not a fastest-adversary proof. [Admission samples](work/admission.json) establish local
capacity ownership and recovery isolation only. Native/runtime/independent release flags
remain false; the known expensive-rejection asymmetry has not been erased.

## Reproduction and invalidation

Use the exact implementation commit above, pinned Rust toolchain and declared Python
requirements. Build `pon_execute`, `pon_work_io`, `pon_admission_load` and
`pon_adversarial_cost` examples with `--locked --release` before native tests.
[The command receipt](qualification/report.json) lists complete invocations and log paths.
[Captured drivers](reproduction/) record actual one-time commands and owned test paths;
they are not production service configuration. Reproduction must use NEW output paths.

The evidence checker verifies file hashes, measured Git blobs, current runtime equality,
concrete executed test names, complete command exits, worker-root agreement, finite
admission accounting and honest experimental scope. It does not decide whether a security
assumption or model is scientifically valid. Changed runtime inputs require a new report;
never edit historical logs or change an acceptance flag to make a gate green.

Raw `.log` transcripts preserve exact runner bytes, including trailing spaces and blank
lines. A narrowly scoped Git whitespace attribute applies only to these immutable
logs; source and document whitespace rules are unchanged. Hash verification still
rejects any modification to a recorded transcript.
