# From-scratch W1 rejection cost diagnostic V1

Status: research diagnostic; no hardness, public-service or production qualification.

The existing [late-rejection example](../../trillionnium/crates/trnm-crypto-primitives/examples/pon_rejection_cost.rs)
acquires a complete honest winner before deriving its false-transcript and
false-product variants. Its original acquisition accounting and V2 contract
remain unchanged. The [new example](../../trillionnium/crates/trnm-crypto-primitives/examples/pon_fresh_rejection_cost.rs)
measures a different acquisition strategy: no valid proof or useful product is
obtained before a false trace enters the full verifier.

## Exact construction and fixed scope

The generator takes the four existing public input classes (dense, zero,
rank-one and sparse), encodes their canonical A/B bytes, and appends 16,384 zero
bytes as the claimed C. It never computes AB or calls a producer. Zero C is a
claim, not a successful product observation. Every sample has an independently
derived challenge. Fake traces are generated by the fixed V1 domain and a
consecutive nonce; all candidates, tickets and failed trials are retained until
the first passing ticket or the 4,096-attempt cap.

The fixed experiment contains eight samples for each of four classes and two
targets: `7f` followed by 31 `ff` bytes, and `07` followed by 31 `ff` bytes. It
does not use an all-`ff` threshold. These are relation-level statements; the
diagnostic does not construct a native header or assert block eligibility.

The trace guess is not compared with an honestly computed trace during attack
acquisition. After acquisition, the complete native verifiers must return
`Transcript`. An unexpectedly valid guess or any other native outcome remains
in stdout and makes the executable fail. A separate scalar reference replay in
the reader checks that the guessed trace really differs; the reader does not
infer invalidity merely from the attack label.

## Accounting

All durations are wall nanoseconds from `std::time::Instant`. They are not CPU,
energy, network, persistence, complete receiver-service or global attacker cost.

Each sample preserves:

- Public material, task hashing, challenge construction and prefix encoding,
  their enclosing setup timer, and instrumentation overhead.
- Every fake-trace and ticket-hash timer, their enclosing search timer, and
  record/serialization overhead. Failed attempts cannot be discarded.
- Final witness allocation/encoding, plus an enclosing acquisition timer and
  its remaining overhead. No setup or proof-acquisition denominator is waived.
- A separate preliminary-filter timer, followed by complete production
  full-limb and scalar-reference verifier timers. The two receiver orders
  alternate across the eight samples.
- Untimed progress observations after both timed receiver calls. Rejection
  must reach the complete original 512 transcript tiles, then stop before
  product reconstruction and `VerifiedWork` construction. Ordered observation
  digests, not counts alone, bind this path.

An exhausted search retains its entire acquisition cost, has no proof and has
no receiver observation. The reader retains these costs in each campaign ratio
denominator and marks the group/campaign incomplete. Thus dropping hard samples
cannot improve the reported ratio. The real fixed targets are unchanged; a
zero-target, two-trial case exists only as a unit-test exhaustion control.

The probe's record construction affects its measured implementation cost. The
raw phase timers make that overhead visible. This is one attainable strategy
on one run, never the cheapest possible adversary or a resource lower bound.

## Independent reader and provenance

The [reader](../../scripts/pon_fresh_rejection_report.py) requires an externally
supplied SHA-256 of the complete raw file. It rejects duplicate JSON fields,
nonfinite/nonnumeric costs, omitted samples or failed trials, changed inputs,
incorrect ticket selection, cost subtraction, reordered/missing kernels,
non-`Transcript` outcomes, incomplete progress and qualification flags.
Raw and reference inputs use the existing descriptor-bound source reader:
no symlink ancestors, no following a replaced leaf, nonblocking regular-file
admission, bounded reads and before/after identity checks. A path-size check
followed by an unbounded read is not used.

The reader pins six scalar-reference/configuration files to their exact bytes
at `da1374a200022bc14dc2bd325cc9ba29dbcd24ab`, checks those bytes before replay,
and reconstructs each claim independently. This is the identity of its relation
reference, not the execution commit of newly built native code. Raw binary
metadata is explicitly a claim, and the summary always retains
`native_source_binary_resource_authenticated=false`. Complete source, locked
Cargo graph, exact binary, resource profile and process-exit observations must
be retained externally using the repository's original native recorder. A raw
file and its reader cannot certify their own execution provenance.

Example release invocation after the original preflight and exact-source build:

```sh
cargo test --locked --release --manifest-path trillionnium/Cargo.toml -p trnm-crypto-primitives --example pon_fresh_rejection_cost
cargo run --locked --release --manifest-path trillionnium/Cargo.toml -p trnm-crypto-primitives --example pon_fresh_rejection_cost > fresh-rejection-raw.json
python3 -B scripts/pon_fresh_rejection_report.py fresh-rejection-raw.json --raw-sha256 <externally-recorded-sha256>
python3 -B scripts/ci/test_fresh_rejection_report.py -v
```

The [reader tests](../../scripts/ci/test_fresh_rejection_report.py) use real
public inputs/ticket searches and the original scalar relation, with explicitly
synthetic clocks and process metadata. Their passing result is not a native
performance run. One synthetic exhausted schedule checks retained accounting;
it is not a claim that the deployed targets exhausted their fixed cap.

## Remaining obligations

This adds no consensus rule, admission permission, current-context bypass or
budget. It leaves all actual W1/MU1 fixed-probability cost bounds unproved.
Source/binary-qualified native observations, honest confirmation under attack,
fresh challenge/identity/connection churn, cross-receiver and restart liability,
WAN behavior and global all-legal-strategy security remain separate gates.
