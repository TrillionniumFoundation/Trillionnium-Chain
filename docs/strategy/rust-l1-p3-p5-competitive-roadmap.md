# Rust L1 Competitive Roadmap（P3 → P5）

更新日期：2026-02-20  
状态：Draft v1（执行版）

---

## 0. 定位与边界

**结论先行**：
- P3 不以“达到 Solana/Sui 绝对吞吐”为目标。
- P3 的目标是把 Trillionnium Rust L1 做成“可持续提速的平台底座”。
- 进入 P4/P5 后，才进入“系统级对标”阶段。

**不变约束（全阶段）**：
1. 不破坏 v1 接口冻结语义。
2. 实验策略不默认开启。
3. 所有性能改动必须附带：bench 数据 + 回归结果 + 风险说明。

---

## 1. 分阶段目标

## P3（6 周）— 工程确定性阶段

### 目标
- 性能：AggressiveGreedy 从“可跑”提升到“可解释、可治理”。
- 稳定性：并发异常、回滚、重启恢复具备系统化验证。
- 运维：最小可观测闭环建立（吞吐、延迟、挑战率、slash 率）。

### KPI（阶段验收）
- Aggressive 在 mixed 20000/2000 场景较当前再提速 >= 15%。
- Aggressive 与 Original 差距收敛至 < 1.8x（阶段性目标）。
- nightly 对回归可阻断（门禁有效，无静默退化）。
- 出具 P3 Decision Memo（Go/No-Go）。

---

## P4（8-12 周）— 系统协同优化阶段

### 目标
- 将优化重心从“执行器局部”扩展至“执行 + 存储 + 网络”的协同。
- 形成可预测的吞吐/延迟曲线，而非单点场景峰值。

### 工作流
1. 执行层：
   - Hybrid 调度器（冲突密度自适应）
   - 热 key 聚簇与优先级调度
2. 存储层：
   - state 访问路径 profile（读放大/写放大）
   - 批量提交与缓存策略优化
3. 网络层（最小闭环）：
   - tx ingress/backpressure 策略
   - 出块前队列行为可观测

### KPI（阶段验收）
- 代表 workload 下吞吐提升 3x（相对 P3 baseline）。
- p99 执行时延波动收敛（波动区间可解释、可复现）。
- 一致性/恢复性门禁无新增红线。

---

## P5（1-2 季度）— 生产级对标阶段

### 目标
- 在真实负载和长期运行条件下，评估“接近 Solana/Sui 某些场景”的可能性。
- 建立生产化性能声明能力（有边界、有口径、有证据）。

### 工作流
1. 长稳压测：
   - 24h / 72h 稳态与突刺混合压测
   - 崩溃恢复、重放一致性、资源泄露巡检
2. 硬件基准矩阵：
   - 标准机型配置 + 成本/性能曲线
3. 真实 workload：
   - 与实际业务任务结构对齐，避免“纯合成数据幻觉”

### KPI（阶段验收）
- 长稳运行中无关键一致性事故。
- 对外可发布性能白皮书（含测试方法、环境、边界条件）。
- 形成“可与主流高性能链对比”的标准报告模板。

---

## 2. 风险与应对

1. **风险：优化只在单场景有效**  
   应对：固定 workload 模板 + 跨模板报告，禁止只报最优样本。

2. **风险：性能提升伴随一致性隐患**  
   应对：state_root 对账和回滚注入测试同步增强，门禁优先级高于性能。

3. **风险：实验参数导致线上不可控行为**  
   应对：实验开关默认关闭，发布分支仅允许白名单参数。

---

## 3. 决策闸门（Go/No-Go）

每阶段结束统一执行：
- **Go**：KPI 达标 + 风险可控 + 运维可观测
- **No-Go**：任一关键门禁失败则延期，继续实验态

---

## 4. 对外表达模板（建议）

> 当前阶段重点不是立即追平 Solana/Sui 的绝对吞吐，
> 而是把 Trillionnium Rust L1 打造成“性能可持续提升、稳定可验证、上线可治理”的平台。
> 在此基础上，逐步推进系统协同优化与生产级对标。
