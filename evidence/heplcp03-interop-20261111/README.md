# HEPLCP03 / TrainingNoUpdateV2 reader interoperability

This is a local, source-pinned engineering validation of Chain's read-only
interop layer. It supplies no ordinary task, real optimizer run, independent
consumer, authenticated Root custody or Hepta FinalUse result. Qualification
remains **HOLD_NO_GO**, authority **DENY_ALL**, activation **false**.

To reproduce the native fixture, create an empty temporary workspace and:

1. Read every blob listed in `source-inputs.json` with `git show` against the
   fixed Hepta commit; verify its Git blob identity, SHA-256 and length before
   copying it. Strip `codex-rs/` from the two library paths. Copy the checkpoint
   codec as `native-codec.rs` in the temporary workspace root.
2. Copy [isolated-workspace.toml](isolated-workspace.toml) as `Cargo.toml`,
   [isolated-Cargo.lock](isolated-Cargo.lock) as `Cargo.lock`,
   [exporter-package.toml](exporter-package.toml) as `exporter/Cargo.toml`, and
   [exporter.rs](exporter.rs) as `exporter/src/main.rs`.
3. Run the following commands with the original Chain initial checkpoint and
   an available Rust toolchain/cache. Compare stdout to `native-fixture.json`
   byte for byte. Offline execution requires the locked dependencies cached.

```sh
cargo run --locked --offline --manifest-path "$fixture_workspace/Cargo.toml"   -p heplcp03-interop-export --   "$chain_checkout/evidence/hepta-real-native-adoption-20261108/chain-reader/no-update-v9/initial.bin"
cargo test --locked --offline --manifest-path "$fixture_workspace/Cargo.toml"   -p codex-hepta-learning-artifacts training_no_update_tests -- --nocapture
```

The initial checkpoint contributes a historical descriptor only. The harness
changes the operation/source-run/source-task identities to explicit fixture
identities before using the original coordinator. The observed cost counters,
Dataset digest and retained publication are test inputs, not measured work.
The independent Python complete-join controls are also explicitly synthetic:
they alter public historical fields and install a **zero signature**. They
cannot be used as owner-signed adoption, receipt custody or FinalUse evidence.

## Local validation and preserved failures

[RESULT.json](RESULT.json) records the current source-file hashes, command
arguments, actual exits/counts and qualification boundaries; `validation/`
retains current command logs. The reader roster has 145 controls (26 adoption,
25 iteration, 13 completion, 11 scope, 29 economics, 24 business and 17 new
trainer-NoUpdate controls), plus 10 selected CI-contract controls and 43 real
Git/source-integrity controls. The historical two completion stdout files and
two #855 business reports are compared **byte for byte**, using their original
bindings bytes rather than reserializing them.

The new suite checks valid Rust cuts/signing bytes, legacy vectors, exact
version/outcome pairing, unknown reason/tag refusal, baseline/Dataset/budget/
actor constraints, no fabricated candidate/Evaluation/Proposal, retained-use
receipts and distinct runs, independently pinned Root rules, unsuccessful or
pending task refusal, v2 business materials and CLI contracts. All existing
consumer/authentication/settlement flags stay false.

Development failures are retained under `failed-observations/`:

- The first test run used a nonexistent historical `review.json` name; the
  actual archived file is `stdout.json`.
- A byte comparison reserialized the bindings, thereby changing their hash.
  It now consumes the original bindings bytes and reproduces the old reports.
- An early v2 business check changed the old HEPLCP01 refusal code. The original
  `LEARNING_CHECKPOINT_VERSION` behavior and old negative test are restored.
- An initial virtual-workspace formatting invocation lacked `--all` and reported
  no targets. The corrected full-workspace command exceeded the retained
  120-second local timeout without producing a conclusive result.
- A strict, offline all-feature/all-target Chain Clippy attempt exceeded its
  retained 120-second local timeout during dependency compilation. No Clippy
  pass is claimed, and no unrelated Rust production source was edited.
- The complete repository checker reaches a historical Markdown link to
  `evidence/pon-v1/README.md`, absent from this sparse local checkout. This is an
  incomplete local materialization, not a complete repository validation pass.

Cargo metadata with `--locked --offline --no-deps`, the embedded native source
inventory check, project preflight and whitespace check are recorded separately.
No full Chain Rust test run, hosted CI run or exact committed-source fence is
claimed here. The repository parent identifies the base; the local selected-file
manifest identifies the changed bytes under test. A later delivery commit and
its hosted head/merge observations remain separately reviewable.
