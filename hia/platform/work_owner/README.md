# Same-worker Work and Host owner

This component carries the complete W1 relation through its original progress
boundaries while a real native worker checks the original acquired Host
authority. It is an implementation boundary for the next Node and batch
integration. Its output establishes a Work relation; it cannot commit a block,
replace a paid-account decision, or grant a new parent authority.

## Runtime

The eight checked HIA sources contain the owner, resumable W1 arithmetic,
embedded Host/resource methods, the literal Linux adapter emitter and the
private fixture entries. The pinned native compiler compiles these sources.
No Python interpreter, assembler, Rust function, dynamic loader, external clock
value, caller TID, caller generation or caller-supplied success bit participates
in the emitted static executable.

The production entry acquires the fixed parent once. Its boot identity, parent
device/inode/owner and five limits remain immutable across the actual child
birth. The child obtains its own actual TID and performs fresh membership,
boot, limit and final-inode checks against that snapshot. A successful complete
proof has 1,099 ordered W1 progress points and 1,101 worker Host checks. A parent
replacement or changed boot does not authorize a new context.

The original complete Host check runs before replay, within every progress
callback, and at the ordinary terminal boundary. Cancellation precedes the
deadline check. The callback checks cancellation/deadline, then Host, then
cancellation/deadline again. An ordinary terminal Host error precedes the Work
result. Only a successful result reaches the final task deadline. A CLOCK1
failure follows the explicit native panic boundary, publishes no product, joins
the owned child, and skips ordinary after-sampling. This is different from a
regular rejected relation or cancellation.

Aggregate resource sampling retains an actually verified parent FD across
CPU, memory and PID reads. All three reads complete before parsing. The FD
closes before the second fresh Host check. CPU deltas preserve checked
subtraction order; memory and PID values remain point observations. Main output
and after-sampling occur only after actual clear-TID join. A shared FUTEX_WAIT
observes that join; private futexes only coordinate child readiness/start.

The private SHA implementation reduces arithmetic overhead while retaining
the original request, task/ticket/transcript definitions, product and all
progress points. The frozen Work/Host/resource sources remain complete build
inputs and are not changed by this component. The private SHA entry exercises
the exact optimized implementation against independently computed SHA-256.

## Interfaces and qualification

The build module takes --output DIR and builds all eight native sections and
the production, fixture and closed-FD images. The qualify module takes --output
DIR --require-trace and performs the complete finite native corpus, primitive
controls, actual syscall traces, trace-admission controls and 18 owned CLOCK1
fault processes. The flag makes missing or denied tracing a failure. It never
changes ptrace policy.

The rust_oracle module takes --repository REPO --bundle DIR --output DIR
--target-dir DIR. It first admits the complete current source and artifact
closure. It copies the complete original source graph, appends only private
cfg(test) children, builds the original Node library with the explicitly bound
Rust 1.95.0 toolchain and rust-src, runs 44 retained original Host tests and
executes 57 original-method histories against the actual native observations.
All original production prefixes, private hooks, tools, std sources, corpus
and independent executable are checked again on every completed path,
including failures. The four native protocol controls without an original API
equivalent remain explicit.

The physical fixtures create files only beneath the private output directory.
They exercise exact original parsing and fresh-check transitions; they do not
represent production authority for the system cgroup parent. The closed-FD
diagnostic image actually closes its captured parent before fstat and observes
EBADF. The native production image cannot enable this fixture.

Reports bind every required source, the exact compiler, emitted images,
complete native input/output frames, actual raw traces and original execution
receipts. Reports are qualification evidence and do not become runtime
authority. Trace exit notifications are optional under strace -qq. Every
notification that does appear must identify one of the actual threads exactly
once after its terminal syscall. An absent notification is not fabricated.
Signal returns are consumed only inside the actual worker's private gate. The
trace audit covers both an interrupted ACK read and delivery immediately after
that read succeeds, without replaying a successful read. Fourteen separate
signal controls retain three accepted observations and eleven corrupt cases.

## Integration limits

The standalone entry owns one finite four-second interval. A Node caller must
retain its earlier private request deadline and original acquired snapshot;
starting this entry cannot renew an intake budget. Paid.history_checkpoint,
the full shared paid account, request intake, batch dispatch, persistence and
Node lifetime have not been closed by this component. Original Rust controlled
CLOCK1 fault equivalence remains separate from the native 18-process fault
qualification. No local fixture grants production fixed-parent qualification.

The original 0.25 CPU / 2 GiB / zero swap / 256 PID profile, four-second service
window with 16 attackers and 1,800-second history limit are unchanged. Finite
native relation or original-method PASS does not imply those full service gates
passed. Failed and unknown development observations are retained separately;
they are never relabelled as a new source candidate's successful result.
