# Neural-work relation and model contribution are different proofs

Status: selected useful-work direction; exact primitive unqualified and unimplemented.
Owners M01/M02/M11; mining workers M03/M15; parameter producers are Hepta owners.

## N1. Actual work carried by a PoN attempt

The target primitive couples a fresh parent/header-bound challenge to verifiable
linear-algebra work drawn from compatible adapter/head/router training or evaluation.
An attempt contains a complete statement: work-program/circuit hash, arithmetic/field
profile, public task/model/input commitments, challenge, shape/cost class and unique
output. It must admit objectively verifiable bounded proofs without asking a panel
whether a model is intelligent. The heavy computation stays outside the pure core.

A concrete research candidate is the arbitrary-matrix PoUW construction in reference
R3. Its authors state a security conjecture; this repository does not convert that
conjecture into a theorem, implementation or permission to copy unreviewed parameters.
Adapter-update execution can supply useful contractions, but the conversion between
ML quantization/floating arithmetic and the proof's arithmetic needs exact range,
rounding and semantic correspondence. A field matrix multiplication is not by itself
proof of a complete gradient update, model improvement, data consent or actual adoption.

The selected design is NOT conventional hash mining plus a decorative model digest.
The reference arithmetic testkit tests target/fork/reorg rules only; its toy lottery
is explicitly non-mining and cannot be admitted as a production work profile.

## N2. Two paths for an already trained small model

A node may finish fine-tuning during ordinary local tasks BEFORE a block challenge
exists. It can publish those parameters as a ParameterContribution, undergo independent
utility/composition evaluation and earn the commons reward without mining a block.
It cannot retrospectively claim that this old training secured a new parent block.

A miner can perform fresh qualified evaluation/continuation/consolidation work against
that contribution or a committed public task under a new challenge. Its accepted work
may win a block; its useful output may separately enter the model-candidate pipeline.
No double-count of the same budget or physical work is allowed. Winning a block does
not automatically admit its expert into the shared model, and a non-winning useful
expert is not thrown away merely because another miner extended the chain first.

## N3. Permissionless work selection

The initial profile admits one exact cost/shape family. Miners may choose eligible
public tasks under the profile's deterministic rules, with a public genesis-provided
maintenance source for an empty queue. No evaluator token, preferred model operator,
prior reputation, bond or private dataset is needed to obtain a mining challenge.
Public task selection must not permit easier instances, early exit, low-rank/zero
inputs, precomputed answers or multiple lottery trials for one cheap computation.
Input blinding/expansion and its hardness model belong to the reviewed primitive,
not to an arbitrary caller-set seed. Inputs that fail those rules are rejected.

Every fee/queue/maintenance rule is authenticated in parent state. A private data owner
cannot halt ledger progress by refusing a label or decryption key. Private data may
support explicitly labelled business evaluations, but not an unavailable consensus
predicate. Open mining does not authenticate the natural-person independence of miners.

## N4. Mandatory primitive qualification dossier

Freeze the precise computation and proof relation; parser and proof bytes; all public
and witness inputs; canonical output; hardware/parallelization/precomputation model;
security parameter; cost floor and distribution; success probability vs target;
verification/proving CPU, memory and byte ceilings; malicious instance analysis;
challenge influence on all charged operations; and independently reproduced vectors.

Explicitly attack old-model reuse, stolen parameters, altered owner/payout, trivial
inputs, changed minibatch metadata, proof-randomness grinding, changing body roots after
work, grinding unused public inputs, partial-trace forging, floating-point tolerance,
cheap verification-result caching and proof outsourcing. Outsourcing honest work is
allowed with the declared payout binding; it must not mint work without expenditure.

A proof of correct computation is not automatically a proof of computational cost.
Transparent setup is preferable; any trusted setup and compromise assumptions must be
named. A TEE quote, training checkpoint log, majority evaluator score, syntactic Rust
verified type or supplied boolean cannot satisfy this work relation. Proof-of-Learning
spoofing and incentive-security limitations are recorded in R4/R5, not hidden.

## N5. Worker lifecycle

ParentKnown -> TemplateFrozen -> AttemptStarted -> OutputProved -> LocallyVerified
-> BlockPublished or StaleRetained. The owner persists exact template, generation,
input/model identities and publication intent. Parent changes cancel or classify work;
a returned old-generation proof can only belong to its old template, never be relabelled.
Bound output pipes, GPU memory, CPU, disk, verification concurrency and cancellation.
A crash resumes only an exact recoverable attempt; missing history is not a fresh key.

Miner key/signing service authorizes identity and payout, not block validity. PoW
competing blocks are not automatically PoCO double-vote offenses. Keep secrets out
of datasets, parameter packages, mining proofs and public telemetry.
